# D1 source-only target delta candidate

This directory is independent of the frozen 7f runner. It does not connect to a target, accept a DSN, execute migrations, enable workers, or expose a provider interface.

`python3 scripts/qa-agent-db-baseline/target-delta/propose.py` prints an offline proposal summary. `--emit` writes only `d1-plan.json` and `d1-candidate.sql` under the owned rebuild artifact directory. It reads source from fixed 7f and evidence from fixed D0 0762e867 using `git show`. Unknown arguments, including a DSN or apply flag, are rejected.

The candidate contains 18 original absent QA function definitions in dependency order. It uses CREATE, never CREATE OR REPLACE, and revokes all client/service grants on each newly created function. It does not add tables/columns, replace existing bodies, alter old ACL/RLS, seed data, register migrations, notify PostgREST, or add the QA trigger. Missing non-QA anchors and existing differences remain explicit blockers; the result is not a runnable QA deployment.

The proposed transaction has local statement/lock/idle timeouts, PostgreSQL major/current-role/required-role checks, exact captured D0 before metadata, an unconditional unresolved-scope exception, exact captured after metadata, and ROLLBACK. It never contains COMMIT or activation. SQLSTATE P0101 = role/version mismatch, P0102 = missing required role, P0103 = catalog drift, P0104 = unresolved blockers/no target write lease, P0105 = after mismatch. Do not remove the gate or reuse this file as a production runner: a later authorized executable patch needs a new reviewed source and complete inputs. Catalog pins do not eliminate concurrent-write risk or verify effective inherited/schema privileges.

`python3 scripts/qa-agent-db-baseline/target-delta/verify_local.py --run` uses the existing fixed-image nonce-owned Fixture only, with no network/ports/mounts. It constructs a finite synthetic legacy representative from fixed source, removes D0-absent objects/columns, restores two body-hash-matching older functions, preserves the native service grant, and adds explicitly synthetic extra structure. It is not a reconstruction of unknown target definitions or an old-snapshot restore. It validates exact existing captured metadata and synthetic row digests across additive definitions and transaction rollback, finite Native create/list/read/negative behavior with local-only grants, and safe STOP preserving postchange records. No worker/provider or full 38-observation matrix runs.

Representative coverage includes synthetic identities, epochs, archived thread, hidden content, revoked consent, exact unknown-ACK input bytes, Task parent linkage and pending budget rows. This proves only these fixture states survive the local operations. It does not establish target deletion/consent/history compatibility, real Auth/JWT, unknown network COMMIT handling, actual provider usage, or real service/device acceptance.

Before COMMIT, any error rolls back the whole transaction. After a future acknowledged COMMIT, use a separately authorized safe STOP retaining all added data and existing states; never drop objects or erase postchange rows to imitate rollback. Unknown COMMIT means stop, preserve original bytes and correlation identity, and reconcile authoritative receipt/catalog under the exact permitted scope. Do not retry or declare rollback from a disconnected client. No such target operation is implemented here.

The seven blocker records in d1-plan.json identify missing source provenance, constraint semantics, cancellation/event dependencies, schema/role/concurrency evidence, existing body/ACL compatibility, column historical semantics, and target authority. Old A–D and conditional E remain separate facts; the rebuild direction and this source/local evidence do not satisfy E or grant a target write lease.
