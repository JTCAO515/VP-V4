## Frozen contract and scope

New append-only `20261002040000_vpj83_journeys_pages.sql` adds `read_assistant_journeys_page_v1(uuid,text)` and two read indexes; it changes no table grants, writer or previous read RPC. The fixed GET `/api/chat/native/v5/journeys[/<cursor>]` uses a separate HTTP module and existing base text/native actor/session gates, including producer-off reads. No NativeSession, native-assistant-http, Ask, Library, fixture or privacy-export source is modified.

One response contains up to 20 literal goal summaries from the current-owner/current-policy/current-consent **latest** conversation, explicit goal scope versions, and sanitized existing goal/Trip relation. It downloads no messages, outputs, task state, structured dates or inferred decisions. Role/eligibility remains authoritative; unknown relations carry no old/foreign Trip ID/head. Latest is not the user's separately selected VP conversation; the UI states that distinction and Open VP does not change their selection.

Cursor `v1.<conversationUUID>.<conversationVersion>.<afterGoalUUID>.<snapshotDigest>` is a path token, not a signed permission. Conversation version is the existing next_sequence; digest pins all bounded goal IDs/scope versions and link versions. Server checks actor/policy/consent/latest before cursor membership/version/digest/after-ID, and checks these bases again before return. Foreign/changed/withdrawn/old conversation cursors return only unavailable, no metadata. Own keyset traversal grants no writes.

Candidate query materializes at most 21 rows (20 plus sentinel); relation materialization calls the original owner/currentness reader at most 20 times within one RPC, not mobile N+1. Each of two digest checks scans at most 101 membership rows and rejects sources over the accepted 100-goal writer limit. Thus the entire RPC is **not** a 21-row scan. New indexes support latest conversation and UUID keyset lookups. It uses existing auth/policy locks, with no new lock across all owner data.

Digest consistency covers conversation/goal/link versions, **not** all Trip eligibility. Trip head/archive/delete changes are checked live by the original relation reader on each page; head/archive can leave the digest unchanged and render unknown. Existing queued-delete trigger changes goal/link versions and invalidates the cursor. The native client holds only one page, replaces it for Next, and Refresh returns to page one; it does not aggregate old pages into a supposedly current relation snapshot. Its shared monotonic 20s request-start clock, policy reread and scope/generation/inactive fences remain. Normal page flow uses Trip list + policy + one summary page + policy (four reads) rather than per-goal requests.

HTTP closes the response schema so accidental messages/extra metadata cannot pass, binds the fixed path, and keeps private/no-store. API and native response limits are 512000 bytes (20 allowed 4000-character texts can approach 480KB with JSON escaping); native checks size before decode. Session transient errors remain unavailable rather than forcing unauthenticated account loss.
