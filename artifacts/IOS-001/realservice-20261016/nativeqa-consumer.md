# NativeQA real consumer source delivery

The initial readiness audit identified absent NativeQA server/transport/consumer seams. Main subsequently fixed the namespace/qa-agent1 contract, assigned server implementation, and accepted this owner's transport interface. This delivery implements the new consumer; shared transport/vault/Root and real target integration remain separate.

## Source and integration interface

- `Features/RealServiceEntry/NativeQA/NativeQAContract.swift` (interface commit a46ba463): DTOs for qa-agent/1, finite NativeQARequest actions and exact `api/qa-agent/native/v1` paths. `request.path` and `.body` are throwing validated getters; submit returns original pending bytes. `NativeQAHTTPResponse(status:body:)` retains ack/error envelope. No noticeVersion is invented.
- `NativeQAStore.swift`: actual session list/create/select, policy/read/explicit consent, durable-command-before-submit, protected request recovery, scoped history/terminal statuses and bounded eight-turn followup. It does not forward to or copy old AskStore and owns no server queue or credential.
- `NativeQAServiceView.swift`: `NativeQAServiceView(transport: any NativeQATransport, chinese: Bool, isActive: Bool = true, onSignIn: (() -> Void)? = nil)`. Main supplies original account navigation callback. zh/en visible real-service/pending/unknown/unavailable/blocked/partial/clarification/technical-failure labels; no fake answers, model selectors, endpoint/secret fields or automatic consent. Semantic fonts, multiline scroll layout and identifiers under native.qa.*. Main owns explicit-only Root/PBX integration.

`@MainActor NativeQATransport` requires trusted `scope`, `request(_:scope:) async throws -> NativeQAHTTPResponse`, and loadPending/retainPending/clearPending. Main's bridge/vault implement these in their own files. This owner does not implement or retain a competing vault adapter. Scope comes only from NativeSession, never decoded caller JWT. Main supplies bounded cookie-free original Bearer HTTP and preserves HTTP status/body. Request/response and physical journal methods must fail on changed scope.

`NativeQAPending` Codable fields: schemaVersion, endpoint, subject, mobileEpoch, sessionID, requestID, policyID, noticeHash, body. The original body contains only requestId/text; whitespace is not normalized. Durability binds endpoint/subject/epoch; process-generation is a live fence rather than persisted identity. Main owns primitive-based independent QA binding, unchanged old pendingAsk and protected-data/logout/cleanup integration. A locked/corrupt/mismatched record blocks sending. No token, Cookie, provider credential, model or budget appears in the pending DTO.

## Safety and behavior

- First send rereads policy and matches the exact displayed policy object; persists and physically rereads original bytes before the only POST. Write or readback failure sends nothing. Concurrent send is blocked by an owned work task.
- Unknown ACK retains the original command. Refresh/reopen reads the same request; no blind retry, new-key substitution or automatic re-POST. Only a protected matching request/session/input receipt clears pending. Missing/foreign receipts, permission failure and changed notice do not erase/rebind it. An authoritative pending row proves admission but not completion; UI continues to show pending and polls history. Existing old Ask explicit same-key retry semantics are unchanged.
- Session selection reads the server's original thread ID; reopening without a retained command shows the real list for explicit selection. It does not claim an in-memory selected pointer is persistence or recreate a local history database.
- Scene inactivity/disappearance cancels owned local work, clears policy/messages/list/pending projection/draft, and preserves the authority's unconfirmed record. Epoch/actor/endpoint/scope generation are checked after every awaited response. View rendering immediately gates on live trusted scope and scene visibility even before the async activation task executes.
- Consent is always user-triggered against the exact reviewed id/noticeHash. Changed notice requires review; there is no fabricated noticeVersion or auto-grant. QA8 bound and pending/reconciliation states block next submission.
- Cancellation of provider work is intentionally not exposed until server confirms the separate existing cancellation receipt contract. Local in-flight cancellation is implemented and tested; it is not advertised as provider cancellation. Explicit pending abandonment UI is not implemented; no unconfirmed command is silently discarded.
