# VPJ-64 — controlled community safety

J2 provides an internal report → independent qualified disposition → actor-scoped receipt and appeal loop, lawful explicit block/unblock, scoped export/delete and the default-disabled publication eligibility seam. `lib/server/community/safety/contract.ts` is the canonical closed wire; `lib/server/community/safety/WIRE.md` records coordinated dependencies and SQL implementation details. This contract does not enable public UGC. J3 publication and J4 propagation through public Explore/search/reference/cache remain separate unfinished work; #238 stays open for that scope.

Native registered Bearer and Ops same-origin Cookie ingress are separate. Both verify expected actor/session before reading the body, recheck live session before dispatch and before returning, and bind outcomes to the exact command/record/op. SQL must resolve and lock the original actor/session root before every read, mutation, cleanup and operation fence. Content UUID knowledge does not confer reading or targeting permission. Existing RLS, session/epoch, source CAS, TTL, consent and TripProposal confirmation remain unchanged.

Current source is internal and permits only author, independently qualified J1 reviewer or explicitly scoped controlled-test reader. Reports and block choices atomically requalify the content and its J1 submissionVersion plus safetyVersion; block target identity is derived internally and never taken as a caller actor UUID. Receipt and audit exports contain only the caller's own metadata. Authors never receive reporter identity or report details. Disposition and appeal reviewers must be independent of the author, reporter and original decision maker as applicable. Qualification never implies official or employee affiliation; trusted J1 disclosures are reused, missing source/rights facts are shown as unknown.

Removing, withdrawing, deleting, blocking or revoking an object makes all J2 content reads and J1 live projections/old receipts requalify immediately. No historical body is copied into a safety receipt. Restoring a safety-removal case changes the current safety frontier only; restoring a J1 rejection requires both independent qualifications against the exact retained current source, stays internal and keeps the compatible J1 version2 with an independent atomic safetyVersion. Withdrawn or deleted bytes cannot be restored.

Ordinary request transport remains 24,000 UTF8 bytes / 10,000 UTF16 units. Operation/abandon outer transport is separately bounded at 49,152 UTF8 bytes; nested original mutation remains 24,000 bytes / 10,000 UTF16 units with exact-byte digest equality. Request cancellation or post-dispatch auth/transport/decode loss produces an unknown acknowledgement, never a rollback claim. Clients persist exact original op/bytes within owner/session/endpoint/epoch scope before sending and do not create another operation until the original is resolved or permanently abandoned. All returned content expires within 30 seconds and is erased from client views/temporary exports on lifecycle or authority invalidation.

The complete `community_safety_module` export includes own reports, own author dispositions, own appeals, own blocks, **authoredDecisions** (the caller's own moderation notes on other users' records without their private reason/body/identity), **readerGrants** (the caller's own explicit held grant metadata, including expired/revoked rows, without conferring content access), own digest receipts, own action audit and own qualification. Every array is bounded at100 with a sentinel; excess fails capacity rather than silently truncating. Scoped delete atomically erases own sensitive statements, target links, authored moderation notes/attribution and qualification/grants while retaining only the inventoried replay fences, record tombstones and minimal audit. J1 original submission deletion is reused. Original unified account export/delete jobs remain explicitly not enrolled; module success is not account-wide success.

`communitySafetyInventory` identifies actual ingress, commands, owned records, export/erasure coverage, minimal retention and excluded cross-module responsibilities. New SQL is append-only, preserves the original `community_workspace(jsonb)` ACL/signature and does not grant roles, enroll real moderators or enable target environments. Real ordinary-auth fixture evidence, SQL persistence, Native and Ops callers must be recorded separately from production/device/human UNRUN.
