# VPJ-80 bounded Shanghai stay-area comparison v1

**Scope:** one delegated comparison of the Jing'an Temple and People's Square anchors for a Shanghai stay, measured only by current transit to Shanghai Railway Station. It does not compare hotels, inventory, booking, safety, quietness or a confirmed Trip. Admission and dispatch reject a goal with an active or terminal Trip link; #572 does not implicitly authorize Trip input. This result has a null Trip ID and no model-accessible confirm, payment, reservation or external-message action.

## Producer to consumer

1. The authenticated native planning policy route returns a separately versioned purpose notice, the pinned Qwen recipient and AMap place-provider identity. Its environment must match the native target. The owner accepts it before delegating. The task route atomically admits one existing metered `ServiceTask` Turn, links it to the current assistant goal/message, pins explicit Memory revisions and marks the `turn_private.work` row as `planning_comparison_v1`. Migration installation creates no policy, consent, user task, worker or budget scope.
2. Existing text/task/grounded claimers select only `execution_mode='text'`. The planning worker claims the same work table and lease counter through its planning-only RPC. The #559 goal context assembler selects relevant current sources for this task-linked message, but its `readyForProvider:false` preview is never an authorization or provider payload. SQL rebuilds and rechecks the current owner, session, goal, task, policy, planning consent and Memory basis before every read and immediately before provider egress.
3. A closed four-action catalog performs `evidence.lookup`, `place.read`, `constraints.evaluate` and `result.prepare`. The first records that qualified area knowledge is not integrated; it does not assert the corpus is empty. The place adapter resolves three exact AMap anchors and makes two bounded current transit comparisons, at most 13 provider requests and no retry. It saves only normalized minutes, transfers, source, observation time and request count. Missing route data stays unknown; at least one route must be observed. Completed tool observations and #571 receipts commit atomically, so a new process can resume after a completed step. A started or unknown action blocks replay.
4. One Qwen C2 model attempt selects only `jingan`, `peoples_square` or `none`. It cannot supply prose, prices or actions. #194's durable budget owns reserve, dispatch, actual settlement, concurrency and cumulative task cost. A missing usage/cost acknowledgement pauses the task without a second paid attempt. Domain code builds every sentence of `comparison/1`; SQL checks the exact text against the validated place observation and requires a recent observation, settled attempt and all prior action receipts.
5. The final SQL transaction marks the existing Turn answered, settles its task capacity, publishes #560's versioned comparison and result event, and completes `result.prepare`. Stale goal/Memory/consent, cancellation, missing cost or invalid content rolls the whole terminal/publication transaction back. The existing native result API/card reads the owner-scoped artifact; no new result store or client copy exists.

## Boundaries and recovery

- The existing #195 hosted CLI can opt into one planning target with closed profile `vpj07-hosted-text-worker/2`, a non-null `{ownerId,planningPolicyId,scopeId}` target and separate `VISEPANDA_HOSTED_PLANNING_WORKER=true`. Profile/1 and profile/2 with `planning:null` retain text-only behavior. Planning UUIDs are canonicalized so discovered text groups and planning use the same owner lane. The native planning flag remains off by default; policy, budget and host provisioning remain explicit.
- Maximum four persisted actions per ServiceTask, one model selection per worker invocation, existing maximum three work lease attempts, 120-second turn guard and finite provider/tool deadlines. Model scope limits separately enforce task/owner spend and concurrency. A waiting/unknown job releases its lease and leaves `paused_unknown`; no hot poll or blind replay. Reconciliation/resumption after an ambiguous paid effect is not provided by this version.
- The synthetic local policy accepts only `synthetic_fixture` place observations, and the Staging policy accepts only `amap`. Fixture artifacts identify themselves in the title. Source existence and synthetic tests do not prove AMap/Qwen/hosted Staging capability.
- Rollback disables new planning admission and stops the planning poller while retaining accepted tasks, artifact reads, revocations and the append-only private records. Do not rewrite an applied migration, retry an ambiguous charge, or fall back to the text worker for a planning row.

The hosted planning poll reuses #195's SQL stop switch, heartbeat, owner serialization, concurrency, lifetime, drain and backoff. It invokes the existing `createStagingPlanningJob`, never a second queue or Coordinator. A service-only read preflight validates the configured owner/policy/scope/model/price/budget before polling, and an exact current Turn/lease branch repeats the budget gate immediately before the compound `place.read` egress. Initial readiness may schedule an unknown-effect cleanup, but that exception cannot authorize the current place claim. The final model reserve/dispatch and all existing consent/basis checks remain authoritative. This read preflight is not a reservation; scope freezes, revocation or other spending can still race after the check or during the bounded 13-call map step. Map charges are separate from the model ledger and remain unverified.

The opt-in AMap credential is removed from the environment after reading, or read from the same private Linux tmpfs as `amap.key` with the existing file ownership/permissions/no-symlink rules. No key enters profile or journal. Planning jobs and usage use separate `vpj80-hosted-planning-job/1` / `vpj80-planning-usage-journal/1` envelopes. Their exact receipt is `validated-planning-usage/1`: attempt.taskId is the ServiceTask, turnId is its current Turn, and policyId is the planning policy captured from SQL input. Legacy `validated-model-usage/1` and the text audit still reject this distinct binding/schema. Unknown journal writes or lost paid responses retain unresolved holds and never authorize replay. Existing ECS/S1 deployment validators remain profile/1-only; this code does not activate or deploy a host.
