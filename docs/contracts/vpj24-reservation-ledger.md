## CAS, deduplication and immutable evidence versions

Owner/account serialization and owner+Trip+reference locks precede mutation. OperationId has an immutable owner-scoped canonical server body digest over Trip+full typed command (JSON object key order does not matter, caller/local field hash never authority). Exact replay checks current actor/Trip visibility and the stored operation first, before expectedRevision or expectedTripVersion write-CAS. If its exact applied revision is still current it returns the original applied snapshot without a second write; altered body/scope conflicts, a superseded or source-redacted operation conflicts and is resolvable through operation read. No retry changes a Trip or emits a second evidence event.

Current table stores one owned reference snapshot. Evidence events append actual reference revisions with operationId, original Trip head, evidenceTier/source kind, explicit user status, server contentDigest/confirmedAt. Operation receipt table is immutable acknowledgement metadata. Sensitive corrected field/source payload is held only in the current snapshot; historical events/operation receipts do not duplicate title/address/terms/external code/source locator. This permits privacy scrubbing without rewriting immutable acknowledgement metadata or leaving old sensitive bodies recoverable. No evaluation-success cache or higher tier is stored.

Server dedup identity is owner+Trip scoped. With an explicit externalReference: supplier+trimmed opaque externalReference (preserve case/internal meaning; no guessed vendor case rule). Without it: canonical normalized kind/supplier/title/startsAt/endsAt/timeZone/address tuple; trim/collapse whitespace, UTC instants and explicit zone, preserve case. Status/terms/source markers are excluded so amend/cancel can update the same identity; changes to fallback identity still use the same selected referenceId with CAS. A different referenceId colliding with either identity returns conflict, not silent merge or cross-owner match. No local hash proves uniqueness. Identity and revision uniqueness are enforced transactionally; any late event/operation insert failure rolls the whole current mutation back.
