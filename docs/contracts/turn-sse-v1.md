# LAUNCH-08 Turn SSE v1

`GET /api/chat/turns/:turnId/events` is an authenticated, owner-scoped replay transport over the existing `replayChatTurn` adapter. It accepts an optional non-negative decimal `afterSequence` query and/or `Last-Event-ID` header. When both exist they must be identical. `Last-Event-ID` and SSE `id` are the canonical monotonic **sequence**, not an opaque event ID. Invalid, conflicting, non-owner, or unavailable requests fail closed through the existing failure taxonomy and never return a stream.

The successful response is `text/event-stream`, `Cache-Control: private, no-store`, and contains only the fixed `turn-sse-v1` fields `turnId`, `eventId`, `sequence`, `type`, and `state`. It has no user message, assistant content, provider payload, token, trace, cookie, identifier, timestamp, or raw database row. Events are strictly increasing, cannot occur after terminal, and use the existing closed state vocabulary. A terminal event is the last event and the finite response then closes.

This runtime is a bounded replay snapshot, not a durable live subscription. When the canonical replay is non-terminal (including empty), the response adds one content-free heartbeat and closes. The Ask client consumes both initial history and SSE through one de-duplicating reducer, then retries the same owner-scoped replay after 2 seconds while the Turn is non-terminal. The current state-only Turn control does not submit a prompt, call a Provider, create an answer/card/proposal, write a Trip, or invent progress. `cancel` remains the existing same-origin, owner-scoped terminal operation.

Rollback: revert the LAUNCH-08 transport, reducer, client and tests together. Existing durable thread history remains readable through its owning route; no Provider call, queue action, migration, new database record, credential, account, Staging, or Production state needs compensation.
