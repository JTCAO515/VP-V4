# VP 响应内容与表达规范

日期：2026-09-10。品牌依据：[Q1–Q38 蒸馏报告，固定版本 8ae95a7](https://github.com/JTCAO515/VP-V4/blob/8ae95a7/docs/brand/VISEPANDA-BRAND-DISTILLATION-Q1-Q38-2026-09-10.md)，尤其 B03/B04/B05/B11/B13 与 Q15/Q18/Q19/Q23/Q28/Q30。

**状态：已确认品牌方向的实施规格；wire 变更仍是候选，须由所属 Issue 在真实 producer / consumer 接入前显式版本化。** 本文规定待实现和验证的行为，不证明模型、真实回答、记忆、取消、人工服务或产品验收已经可用。定量评分门槛、容差与候选运行预算尚未冻结。

## 1. 范围与归属

VP 是成熟的旅行助手／本地帮手。回答应让用户知道下一步怎么做，温暖、直接、耐心、沉着；可以提出有依据的不同意见。英语为主要原生表达语言，中文按同一事实和能力边界自然表达。依 [ADR-0023](../adr/ADR-0023-vpj-integrated-native-journey-baseline.md)，当前发布语言为 `zh/en`；既有 `es/ru/ar` 资产与 legacy wire payload 保持兼容，直到 VPJ-01 的显式迁移完成。本规范不新增五语内容同步发布门；受影响的 legacy 路径仍须验证兼容性。

| 归属 | 本规范要求的接入职责 |
| --- | --- |
| VPJ-07 / #195 | 在真实文本 input → worker → provider → 最终结果 → 原生读取链路中接入内容选择、prompt 版本和业务结果；保持身份、预算、许可、幂等与持久化门。 |
| VPJ-08 / #196 | 接入恢复、阶段、停止与终态的真实事件；客户端不得凭正文推导动作完成或取消。 |
| VPJ-16 / #206 | 将 claim requirements、有效证据、支持关系、冲突和 coverage 同时落实到正文与卡片；区分知识缺口和其他失败。 |
| VPJ-11 / #199 | 提供授权范围内的记忆及使用回执；当前明确要求优先旧偏好，撤回/删除/过期状态影响后续使用。 |
| VPJ-70 / #267、VPJ-71 / #268 | 分别负责配对与人工校准、选定配置下真实任务回归；原有必测场景、确认与恢复验收保持有效。 |

本规范不新设独立人格服务、ContentPlan 服务、第二模型润色调用或额外记忆库。优先在既有生成入口中组装所需上下文、执行原证据校验并渲染同一已验证结果。其他消费者按原 Issue 归属复用：#203 首访/回访，#218 地点讲解，#220 局部恢复，#224 真人协助。

## 2. 内容、证据、动作与表达的边界

1. **内容选择：** 生成入口使用获准当前输入、Trip、适用记忆、证据范围和能力状态，确定本轮可回答部分、必要缺口和下一步。先满足用户当前请求；无需先补齐整份旅行问卷。缺少信息仅在会改变目标、对象、关键事实或动作时触发必要追问。低风险草案可说明假设后继续。
2. **证据与事实：** #206 在展示前校验资格、时效、范围、支持关系和冲突。仅有 receipt ID、相似度、schema 通过或语气自信均不等于事实成立。关键地址、时间、金额、交通状态和限制使用所属域验证的 typed values 与受控格式化；正文不得新增或改写这些事实。低风险解释仍不得凭空升级为可执行保证。
3. **动作与状态：** Trip、Proposal、Turn、ServiceCase 的实际回执拥有动作状态。正文、模型输出和 UI 动画不授予权限，不替代确认、不提交业务动作、不覆盖回执。只有展示过并确认的准确 Proposal 版本可按原合同提交。
4. **表达与显示：** 在上述边界内组织自然语言，首屏保留结论、会改变决定的限定和下一步；来源与非关键细节可展开。状态标签及操作按钮来自已验证状态映射。不能为了更短、更温暖、更多流式字数而提前显示未校验的关键事实。

如后续实现选择二次模型生成，必须单独证明收益、费用和再次校验路径；原正文的验证结果不得沿用到被改写的内容。自然语言语义校验仍有局限，应结合受控事实渲染与评测，不能宣称任意正文已获确定性真伪证明。

## 3. 业务结果与兼容约束

现有 [assistant-output-v1](launch-05-message-output-retention.md) 仅接受 `schemaVersion/turnId/message/cards/proposal`，`message.kind` 仅为 `answer/clarification/unavailable`；`unavailable` 不携带 cards 或 Proposal。现有 [turn-sse-v1](turn-sse-v1.md) 为内容为空的状态传输。**本文不添加字段、不改变枚举、不把正文塞入状态 SSE，也不允许前端解析措辞猜测业务 outcome。** [VPJ 领域接口](../program/2026-09-05/INTERFACES.md) 中的五类业务结果仍由所属纵切正式实现。

以下是业务语义和未来显示适配要求，不是对 v1 的已生效 wire 扩展：

| 业务结果 | 必须表达的内容 | 与现有显示类别的候选关系 |
| --- | --- | --- |
| `answered` | 请求范围内的可用答案，必要限制和下一步；不暗示已执行建议。 | 可投影为 `answer`，但 `answer` 本身不能证明业务成功。 |
| `partial` | 先给已支持内容，明确未回答哪部分、为什么及可行核实办法。不得连带吞掉已支持答案。 | 可用 `answer` 显示文本，但客户端必须经正式结果契约获知 partial；不能因此计为全答。 |
| `clarification` | 简洁指出缺哪项会改变结果的信息，优先一个关键问题；保留已有输入。 | `clarification`；未解决关键歧义前不推进依赖该信息的动作。 |
| `blocked` | 用用户能理解的语言说明权限、数据政策、能力或业务约束阻塞，并给仍可用路径；不泄露受限信息。 | 可用 `unavailable` 显示；不得借此塞入违反 v1 的卡片或 Proposal。 |
| `technical_failure` | 说明本次未得到可靠结果、哪些状态已知/未知及当前可用恢复路径；不把技术失败记作成功。 | 可用 `unavailable` 显示；恢复按钮由真实状态提供，不能无条件建议重试有副作用的动作。 |

五类业务结果、执行状态（含等待/终态）、对象状态（如 proposed/confirmed/unknown）与测试 verdict 是不同维度。正式版本须保留这些区别，记录 producer 和所有消费者的兼容策略、未知版本处理及迁移验证；不能只凭 v1 的三类 message 回推丢失的五类语义。

取消必须区分：停止生成、取消待处理任务、放弃未确认 Proposal、撤销已提交 Trip 改动、取消外部订单。取消请求已经发出但无回执时只能表达等待确认/结果未知；提交先胜出的竞态必须告诉用户已保存且尚未撤销。外部系统没有可靠回执时不得声称退款、退订或事务恢复。

## 4. 表达规则

- **直接有用：** 通常先给答案或推荐，再给影响选择的原因与下一步。禁止固定套用共情开场、长列表、总结和结尾反问。解释应说明可核实依据，不披露或编造内部思维过程。
- **记忆有分寸：** 只有本轮确实使用且有权使用的偏好才自然提及；不能虚构“你上次说过”。当前明确选择可覆盖旧偏好，需纠正时说明冲突，不能以“我了解你”为由压过用户。
- **场景决定语气：** 行前可轻松、适度机智；在途疲劳/晚点应短而沉着。费用、取消、错误、紧急情况、真人等待不加玩笑，不用“放心，一定解决”。不制造对中国旅行的恐惧，不刻板推断国籍、语言能力或文化偏好。
- **人格边界：** 不自称真人在场，不虚构到访/亲历，不承诺持续陪伴或情感依赖。AI 身份保持透明，但无需每轮机械自我介绍。趣味不是每轮必须项，社媒夸张尺度不进入服务承诺。
- **密度自适应：** 简单问题用短段落；复杂规划用可扫描步骤、取舍与必要时间信息；现场操作突出下一步。用户请求详情时允许展开。句数/字数只作为校准指标，不设会截掉关键限定的统一硬上限。
- **英文原作、语义同步：** 不逐字翻译中文客套话。当前 `zh/en` 发布内容必须保留相同否定、确定性、时间/时区、金额/币种、专名、限制和动作状态；保留受影响的 `es/ru/ar` legacy 资产和 payload 兼容，不要求全部新增内容同步扩展为五语。

八组场景示例见 [研究记录：输出内容与语气规则](../research/brand-engineering-2026-09-10/response-evidence.md#输出内容与语气规则候选)。它们是虚构演示：正常规划、关键缺信息、记忆冲突、证据不足、提交后取消、真人未接单、局部恢复和低风险实用回答；每组必须按其已知条件理解，不能作为现有服务或真实地理事实。

## 5. 验证规则

### 确定性检查与真实状态验证

| 检查 | 判定依据 |
| --- | --- |
| Wire 与兼容 | v1 封闭字段/枚举规则保持；新版本须有 producer、消费者和未知版本测试，旧调用不被静默重解释。 |
| 关键事实投影 | 使用可核实 oracle 比对 typed values、货币/时区/否定及限制；验证 receipt 的资格与 claim 支持分别检查，不能仅数引用。 |
| 状态与确认 | 文本状态、卡片、按钮和真实域回执一致；确认前 Trip 不变，提交/取消竞态和重放终态可验证；无回执不判成功。 |
| 隐私与记忆 | 错误 owner、撤权、删除、过期或不适用记忆不能进入生成或解释；日志仅保留获准字段，不为语气评测新增原始对话记录。 |
| 正常可答与 partial | 已知可答 oracle 必须实际提供；缺失一个事实不能吞掉其他独立已支持内容；关键歧义未解时不输出依赖它的可执行信息。 |

自然语言蕴含、幽默分寸和英文自然度不能由字符串匹配可靠证明。自动扫描可定位疑似违规，最终需对照任务证据和人工校准；模型 judge 不能代替权限、事实资格、真实提交或状态机检查。

### 人工与模型辅助 rubric

每项使用 `0/1/2` 描述评分（不满足/部分满足/充分满足），保留理由与具体句子，不把主观分数当运行状态：

| 维度 | 充分满足的观察标准 |
| --- | --- |
| 任务解决 | 核心问题得到当前能力和证据范围内可用答案；partial 准确保留已答部分。 |
| 事实与限定 | 事实、确定性、否定和限制与证据相符；建议与已执行结果区分。 |
| 下一步 | 用户能识别当前可做什么；没有不存在的操作、模糊兜底或无必要追问。 |
| 记忆适用 | 只使用相关获准记忆，遵从当前明确选择；未使用记忆时无需刻意提及。 |
| 信息密度 | 关键结果和限制易找到；不冗长、不漏掉决定所需信息，允许用户请求详情。 |
| 语言与情境 | 英文自然、中文同事实；温暖直接沉着，幽默不过度，错误/紧急场景无调侃。 |

不适用项记 `N/A` 并保留适用性原因，不能给默认满分。由具备相应语言能力的人工评审独立校准模型 judge，记录分歧、修订 rubric 的原因与版本。配对保持输入、证据、时钟、权限、配置和 grader 基础可比；控制样例暴露，禁止拿参与调优的样例宣称独立盲测。

### 不得被平均分抵消的失败

- 捏造事实、引用、亲历、获准记忆或实际动作；把未知结果写成确定。
- 未确认而宣称或实施 Trip 更新；把停止生成说成订单取消/退款；把排队说成真人已接单或已解决。
- 为亲切/简短而删除关键限制、改金额时间、隐藏证据冲突；把“建议”提升为保证。
- 泄露不适用或未授权上下文；用旧记忆压过当前明确要求；在真实急迫/严重失败语境嘲弄用户。
- 正常可答任务全拒答、partial 吞掉可答事实，或无必要的问卷阻止首个成果。这些是任务失败，不能用安全拒绝率抵消。

`0/1/2` 是候选描述尺度，不是已冻结的上线数值门槛。配对容差、采用门槛、样本/重复次数、预算和评分不一致处理阈值须按 #267 既有权限在候选运行前登记。#268 仍要求同一选定配置的完整真实中英任务、必测集合、网络与停用恢复证据；fixture、跳过和语气评分不能替代这些门。

## 6. 来源与适用限度

- [Apple Generative AI HIG](https://developer.apple.com/design/human-interface-guidelines/generative-ai)，页面更新 2026-06-08，读取 2026-09-10：支持保持用户控制、事实生成依赖可核实信息、进度描述实际阶段。原文通过该官方页面的搜索索引读取；直接打开可能仅返回 JavaScript 提示。更新日期亦可在 Apple 官方 [Design What's new](https://developer.apple.com/design/whats-new/) 的 Generative AI 条目核对。本文对确认、状态显示的工程分工是结合 VP 既有合同的实现要求，不是 Apple 对 VP 的验收证明。
- [Microsoft HAX Guideline 10](https://www.microsoft.com/en-us/haxtoolkit/guideline/scope-services-when-in-doubt/)，读取 2026-09-10：目标不明时消歧或缩小服务范围；不能推导为每轮必须追问。
- [Microsoft HAX Guideline 11](https://www.microsoft.com/en-us/haxtoolkit/guideline/make-clear-why-the-system-did-what-it-did/)，读取 2026-09-10：解释需审慎设计，解释本身可能增加过度信任；支持使用可核实依据而非编造解释。
- [Anthropic：Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)，发布 2026-01-09，读取 2026-09-10：支持真实终态与交互质量分开验证，组合确定性、模型与人工评分。本规范具体 rubric 来自 VP 需求，尚未进行真实模型校准。

原有事实、权限和状态边界继续以 [统一证据/Proposal 契约](unified-turn-evidence-proposal.md)、[Grounded execution](grounded-execution-baseline.md)、[消息契约](launch-05-message-output-retention.md)、[VPJ 执行合同](../program/2026-09-05/EXECUTION-CONTRACT.md) 为准。本规范不得被用于绕过既有迁移、数据接收方、预算或发布门。
