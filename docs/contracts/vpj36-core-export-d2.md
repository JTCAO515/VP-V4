# VPJ-36 D2 core export — draft durable contract for Main/SQL owner

D2 exports current-owner core Trip and connected modules. It does not complete
D3–D5, execute deletion, change financial retention or claim provider/backup coverage.
The original all-data privacy request remains an intent; never turn its old202 into
completed. A separate request-bound export job carries actual execution receipts.

## Admission, execution and artifact

Native POST `/api/privacy/native/v1/exports` body exactly `{requestId,confirmed:true}`.
Ordinary verified Native Bearer, no cookies/Origin/caller owner. SQL reuses the
existing all-data export request boundary and requires current native epoch plus
server Auth session created within five minutes, matching D1 reauthentication.
SQL must reject delete action, foreign/altered request scope and token refresh as
reauthentication. New export intent may be recorded atomically through the existing
privacy request RPC; old intent alone cannot start or complete a job.

Persist immutable requestId/owner/sessionId/epoch/scope version and job generation.
States: queued → running under bounded lease → ready_partial|ready_complete,
or failed/expired. Claim is CAS and returns leaseId/ownerId/generation/expiresAt.
Worker owner comes only from the durable lease. Validate lease/current owner/session
before reads and before atomic artifact+receipt commit. An expired/crashed lease
never writes a terminal artifact; retry reads request state first. No jobs/Storage
activation or new role/grant is part of this TS work.

Artifact: bounded canonical JSON bundle, SHA256 plaintext digest, AES-256-GCM
ciphertext with requestId/owner/generation as associated data, server keyId, nonce/tag,
byte count and expiry. Persist ciphertext and terminal module receipt atomically in
private job storage; no public object URL or unprotected filesystem. A missing
approved key/config keeps execution disabled. SQL owner must fix exact RPC names,
params and closed receipts before TS runtime consumer installation.

Policy is explicit server-only enabled/environment/maxRunMs/artifactTtlMs/
downloadTicketTtlMs/maxPages/pageSize/maxBytes; no live duration default or target
configuration is supplied. Hard local code caps: 1000 pages, 100 rows/page, 8MiB.
Jobs retain only request-bound execution metadata; purge expired generated bytes
and tickets, account deletion cascades them, and export itself never deletes source
records. No raw credentials, worker keys, private keys or raw download token in rows/logs.

## Module collection and consistency

Closed first manifest: trip, conversations, results, profile, memory, turn,
user_artifact, brief, entitlements. Missing handler is unavailable/HANDLER_MISSING,
not an empty successful module. Existing assistant Conversation and result export
RPCs are live bounded traversal: collect every page/section with exact owner cursor,
reject malformed/repeated cursors, and report partial/LIVE_TRAVERSAL rather than a
consistent snapshot claim. New request-bound Trip reader contract belongs to SQL
owner; TS cannot invent an existing privileged Trip export RPC. Partial delivery is
explicit when module/source/capacity is missing. No215 default-revoked metadata is
quietly added to current service authority.

## Protected owner download

GET `/api/privacy/native/v1/exports?requestId=UUID` returns exact job receipt only.
POST `/api/privacy/native/v1/exports/{requestId}/download-ticket` requires current
owner Native session; body empty. A server-generated random256-bit challenge is
returned only to that owner and stored only as SHA256, bound to exact request,
artifact digest/generation, current session epoch and trusted expiry. Admission/
ticket reauthentication/currentness checks are SQL authority, not caller timestamps.
GET `/api/privacy/native/v1/exports/{requestId}/download` requires the current
ordinary Native Bearer plus `X-Export-Download-Token`; no token/owner in URLs.
SQL must match current owner/session, token hash, artifact generation/digest and
expiry atomically. Download verifies/decrypts exact protected bytes and plaintext
checksum, then serves private/no-store attachment with fixed JSON media type.
Expired/missing/foreign/revoked credentials reveal no payload. Downloaded files
cannot be remotely recalled. Token issuance/replay semantics are fixed by SQL owner.

## Minimal durable RPC proposal — ready for Main review

One new domain entry: `public.privacy_core_export_v1(p_action text,p_input jsonb)
returns jsonb`. Initial EXECUTE is revoked from PUBLIC/anon/authenticated/service_role;
Main must separately review role-specific action guards/any exact future permission.
No pre-existing service grant is presumed to cover this entry or its generated bytes.
Every input is a closed object. No action accepts caller owner/session/epoch.

| Action | Exact input | Authority | Closed response |
| --- | --- | --- | --- |
| request | requestId, confirmed:true | current owner + recent server Auth session | privacy_export_job/1 receipt |
| read | requestId | current owner/session | privacy_export_job/1 receipt |
| claim | requestId, operationId, maxRunMs, expectedEnvironment, expectedKeyId | service, operator-disabled worker | privacy_export_lease/1 or unavailable |
| validate | requestId, leaseId, generation | service, current durable lease | privacy_export_lease_state/1 {current:boolean} |
| trip_page | requestId, leaseId, generation, afterTripId:null|UUID, limit:1..100 | service, current lease, owner from job | trip-core-export/1 page |
| commit | requestId, leaseId, generation, artifact, modules, coverage | service, current lease + session/owner recheck | privacy_export_job/1 ready receipt |
| execution_receipt | requestId, leaseId, generation, expectedArtifactDigest | service, original execution binding (including terminal) | privacy_export_execution_receipt/1 |
| fail | requestId, leaseId, generation, reason:SOURCE_UNAVAILABLE|INVALID_OUTPUT | service, current lease | privacy_export_job/1 failed receipt |
| ticket | requestId, operationId, tokenHash, ticketTtlMs | current owner/recent session | privacy_export_ticket/1 bound metadata |
| download_prepare | requestId, operationId, tokenHash | current owner/session | privacy_export_download/1 encrypted artifact envelope |
| download_consume | requestId, operationId, tokenHash, artifactDigest, generation | current owner/session | privacy_export_download_consumed/1 |
| purge | operationId, limit:1..100 | service | privacy_export_purge/1 {removedArtifacts,removedTickets} |

Request admission atomically calls the existing all-data export intent function
or verifies its exact export receipt, then creates a separate job. Do not update
old privacy intent status/execution. Same request/action/confirmation replays the
same job; delete/foreign/request-scope drift is rejected. No restart after expiry
under the same request ID. A new explicit request is required.

`privacy_export_job/1` exact fields: kind, requestId, scope:"core-export-d2/1",
state:"queued"|"running"|"ready_partial"|"ready_complete"|"failed"|"expired",
generation:positiveSafeInt, createdAt:UTCms, completedAt:null|UTCms,
artifactDigest:null|lowerSHA256, artifactBytes:null|nonnegativeSafeInt,
artifactExpiresAt:null|UTCms, modules:moduleReceipt[], allUserDataCompleted:false.
No owner/session/credential/lease token or private-body disclosure in owner receipts.
Queued/running: modules=[], artifact fields=null, completedAt=null. Failed is a
terminal error with UTC completedAt but modules=[] and every artifact field=null;
its termination timestamp never implies successful completion or delivery. Ready state must
agree with module coverage, committed artifact and completedAt; expired retains
only minimal receipt metadata. complete covers declared D2 modules only, never
all user data or D3–D5.

`privacy_export_lease/1` fields: kind, requestId, ownerId, leaseId, generation,
expiresAt, reused. Job admission captures session/epoch internally; claim/check/
commit must reject revoked/replaced/deleted owners. Same operation reads its same
lease/terminal state, not an extended deadline. Expired lease may be reclaimed by
new service operation with incremented generation; prior generation cannot publish.
No external artifact exists before commit. Commit lost ACK: worker reads exact job
status/digest first, never re-exports, overwrites or creates an alternate artifact.

Artifact exact fields: schemaVersion:"privacy-export-artifact/1", keyId:ASCII1..128,
nonce:base64url12bytes, tag:base64url16bytes, ciphertext:base64url<=8MiB,
plaintextDigest:lowerSHA256, plaintextBytes:1..8388608, expiresAt:UTCms.
SQL stores private bytea ciphertext/nonce/tag and metadata, not external Storage.
AAD is canonical JSON `["privacy-core-export/1",requestId,ownerId,generation]`.
The generated plaintext JSON bundle must fit maxBytes including all receipt/notices;
worker computes SHA256 and encryption before attempting the single atomic commit.
Artifact TTL is explicit worker trusted policy, bounded by its supplied TTL and
server validation. Job/ticket expiry never extends an existing artifact deadline.
Account deletion/expiry purge remove generated bytes and token hashes; source
product data and financial records remain untouched.

Trip page exact envelope: schemaVersion:"trip-core-export/1", section:"trips",
items:[{tripId,title,headVersion,confirmationState,content}], hasMore:boolean,
nextCursor:null|UUID, sectionComplete:boolean. Read owner/current confirmed snapshots
from job authority only; never mark projection lag/missing snapshot as an empty
successful Trip. Live bounded collection is partial unless SQL owner supplies an
explicit snapshot guarantee. D1 tombstones remain authoritative; this entry creates
no source write/fence/deletion and cannot restore deleted Trip content.

Ticket issuance binds requestId/generation/artifactDigest/current subject/session/
epoch plus expiresAt. It stores SHA256 only. Exact reply: kind:"privacy_export_ticket/1",
requestId, operationId, generation, artifactDigest, expiresAt. HTTP generates raw
random token once, submits its hash, returns it only on an acknowledged matching
receipt; issuance ACK loss does not return an unbound token. Owner may request a
new operation/token; issuing one invalidates outstanding predecessor tickets and
never renews artifact expiry. Same operation with a changed hash conflicts.

Download prepare returns kind:"privacy_export_download/1", requestId, operationId,
generation, ownerId, artifactDigest, artifact (encrypted envelope), ticketExpiresAt.
Prepare must validate exact owner/session/hash/expiry and pin artifact generation.
HTTP validates/decrypts/checksums all bytes before consume. Consume repeats current
owner/epoch/hash/expiry/generation/digest and atomically marks ticket used; only an
acknowledged `privacy_export_download_consumed/1` matching request/operation/
generation/digest allows sending bytes. Token is one-use: replay/lost consume ACK
returns consumed/unavailable without bytes. Do not silently replay or extend a token.
If delivery fails after consumption, a new explicitly requested ticket operation
is required; downloaded files cannot be recalled. This conservative lost-ACK rule
prioritizes confidentiality over transparent download retry.


## Main review corrections — fixed early contract

Worker lost-ACK recovery uses service-only `execution_receipt`, not the owner `read`
entry and not a renewed/current lease. Exact input is requestId/leaseId/generation/
expectedArtifactDigest. Closed response is
`{kind:"privacy_export_execution_receipt/1",outcome:"terminal"|"unknown",receipt:jobReceipt|null}`.
Only the original execution lease/generation/digest may match a terminal job; keep
that binding after commit/fail. Revalidate captured owner/session/epoch even after
terminal state. A mismatch, deleted/revoked owner or unknown outcome never renews
or re-exports; unknown preserves uncertainty. No stored user JWT/impersonation or
service access to owner-only read is needed. Terminal means exact acknowledged
ready receipt; failed can be returned only for the same original execution and
must carry no artifact. No alternative ready artifact under the same request.

Hard safety limits, in both SQL and TS (not enabled live defaults): maxRunMs <=90000,
artifactTtlMs <=86400000 (24h), downloadTicketTtlMs <=300000 (5min), pages <=1000,
pageSize <=100, plaintext <=8388608 bytes. AES-GCM raw ciphertext is the same byte
length; nonce12 + tag16 add at most28 raw bytes, with separately bounded key/metadata.
Supplied durations must be positive integers. Authenticated ticket callers cannot
extend beyond either SQL cap or immutable artifact deadline. Server HTTP policy
may choose shorter durations; missing/disabled policy still does nothing.
SQL final ticket/consume validation must be current even if the caller supplies
maximal durations. Ticket issuing/consuming never updates artifactExpiresAt.

## Producer configuration and operation-ID binding

Server-only `VISEPANDA_CORE_EXPORT_POLICY` has exactly enabled/environment/maxRunMs/
artifactTtlMs/downloadTicketTtlMs/maxPages/pageSize/maxBytes and no defaults; every
number is positive and subject to the hard limits above. `VISEPANDA_CORE_EXPORT_KEY`
(for HTTP decryption) or the private worker key file supplies exactly
`{algorithm:"AES-256-GCM",keyId,key:canonicalBase64url32bytes}`. No default/random
production key. Private SQL policy remains independently disabled without an
operator seed, and validates every action limit/keyId against its immutable snapshot;
server configuration does not grant access or seed it.

Download includes `X-Export-Operation-ID` matching the acknowledged ticket
operationId, alongside secret `X-Export-Download-Token`. UUID/base64url full-value
validation rejects duplicate-combined headers. Owner/session/epoch always come
from authenticated SQL authority, not this public operation-ID correlation value.
No query token, new download operation or fallback to a different ticket.

`node --experimental-strip-types lib/server/privacy/export-runner.mjs REQUEST_UUID`
is the bounded operator consumer, default disabled with no scheduler. It requires
explicit `VP_PRIVACY_EXPORT_WORKER=true`, local|staging environment matching policy,
trusted DB URL (staging hard-bound), absolute0600 DB/key files and an already-admitted
request. Local additionally requires the existing disposable-stack flag and
loopback URL. Production is not enabled by this runner. It claims one job, validates
its exact lease between module reads, collects real existing export RPCs plus the
new job-bound Trip reader, encrypts then commits one artifact. No secret or module
text is printed, and unknown completion is not reported as success.


## Fixed claim environment/key expectation (Main)

Service claim requires expectedEnvironment and expectedKeyId in addition to request/
operation/maxRun. Environment comes only from the validated server target; keyId
comes only from the validated server encryption provider after enabled policy.
SQL compares both exactly with its enabled private policy, never selects/overwrites
policy from them. Old claim shapes are rejected, with no inferred default environment
or key. Successful claim freezes the policy revision/snapshot internally. Validate,
Trip reads, commit and service execution_receipt require both the frozen snapshot
and currently enabled/unrevoked policy; a policy change blocks publication/recovery.
No new owner field, public private-policy read or expectedPolicyRevision is added.


## SQL execution deadline versus delivered artifact expiry

SQL stores internal jobDeadline=min(policy.validUntil, admissionTime+2*policyTTL),
with <=48h hard bound. Execution lease is capped by supplied maxRun, policy90s cap
and jobDeadline. Commit requires a live lease but artifact expiry is independently
clamped to min(workerExplicitExpiry, commitServerTime+policyTTL, jobDeadline), never
to leaseExpiresAt. Worker explicit expiry must be future and <=24h hard cap.
Ready/download replies expose the actual clamped artifact expiry; TS accepts a
shorter future expiry and uses the authoritative returned value, not equality to
its original submitted time. Commit recovery remains pinned to original request/
lease/generation/plaintext digest. This code rule supplies no enabled live TTL.


## Existing Conversation-associated export sections

Conversation includes its original five sections plus messageSources and travelIntakes.
The two additions use only already-authorized service-only domain functions:
assistant_message_source_export_owner_v2(owner, after_message, limit), schema
assistant-message-sources-export/2 with last item messageId; and
assistant_travel_intake_export_owner_v1(owner, after_id, limit), schema
assistant-travel-intake-export/1 with last item message_id. Their closed page envelope
has no section field. Owner always derives from validated job lease; exact UUID
keysets/100-page rows and repeated/backward/last-anchor guards apply. No broad RPC
allowlist match, new permission or215 private metadata is added. A later source
failure after collected pages preserves a partial/SOURCE_UNAVAILABLE module receipt,
not a false complete section. All live-traversal limitations remain explicit.
