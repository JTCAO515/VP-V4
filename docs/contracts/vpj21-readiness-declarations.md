## Closed owner RPCs and wire

`public.read_readiness_declarations_v1(p_trip_id uuid,p_task_id uuid) returns jsonb`.

`public.save_readiness_declaration_v1(p_trip_id uuid,p_task_id uuid,p_expected_basis jsonb,p_expected_revision bigint,p_operation_id uuid,p_declaration jsonb) returns jsonb`.

Basis is exactly `{taskId,taskTurnId,conversationId,goalId,goalVersion,tripId,tripVersion,dateBasis,taskBasisDigest}`. IDs are canonical lower UUIDs, goalVersion1..10000, tripVersion0..safe integer; hashes are lower64hex. All fields come from locked current source; caller basis is only CAS equality, never owner/date authority. Server dateBasis hashes the full current `trip_days` ordered date/timeZone tuples (null zone explicit), including the empty undated array. Consumers use the returned hash; the old request-local `index.ts` JSON-stringified date hash is not the save authority. taskBasisDigest includes the current source message/sequence, Task root/latest Turn/thread/scope/policy/consent, current goal and confirmed link operation/version; it is independent of declaration revision and is not an assessment result.

Declaration is exactly `{scenario,city,locale,subjectId,applies,resourcesReady,conditionsChecked,checkAt}`. Scenario enum connectivity/payment/admission/address/transport; city shanghai/beijing/guangzhou/chongqing; locale zh/en; subjectId null or existing ontology slug `^[a-z][a-z0-9_-]{0,127}$`; nonnull subjects allowed only admission/address (their null remains supported unknown). Answers unknown/yes/no. checkAt now/unknown or bounded valid RFC3339 explicit-offset timestamp, max40chars; no inferred appointment/eligibility or reminder. Stored ruleVersion is server constant `readiness-actions/1`. No document number, free text, photo, provider/source body or verified-ready status.

Success is exactly `{kind:"readiness_declarations",basis,revision,declarations,declarationBasis:"explicit_user_report",state:"empty"|"current"|"stale",ruleVersion:"readiness-actions/1"}`. Revision0 denotes no ledger; saved revision positive and bounded safe integer. At most5 distinct scenario records, ordered by fixed scenario enum. These are explicit user reports (`source_kind=user_input` internally), not true readiness or fulfillment assertions. read returns current basis even when the stored basis changed, same monotonic ledger revision, declarations[] and state stale. No old yes is exposed under a new date/task/goal/link basis. Saving after a basis change clears every old scenario before saving the submitted one; no other old yes is carried forward.

Valid CAS/basis/operation conflict returns exactly `{kind:"conflict"}`; lost/foreign/terminal/source-policy authority returns `{kind:"unavailable"}`. Malformed closed input raises INVALID_INPUT. Auth/session failures use existing UNAUTHENTICATED/SESSION_REPLACED errors. Save records immutable scope/input digest and exact minimal success receipt under operationId, atomically with the ledger. Exact same-operation replay is served only after current actor/source/basis validation; changed input/scope or changed current authority never exposes a historical report as current. No second source writer or caller-supplied epoch/owner/date hash.
