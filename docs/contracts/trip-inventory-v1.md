# Native Trip inventory v1

AGENT-013 / [#264](https://github.com/JTCAO515/VP-V4/issues/264). Producer: the existing Native Trip adapter's ordinary Supabase client, original `authenticated()` and canonical `getTrip(id)`. Consumer: `evals/harness/runtime-trip-inventory`. No new data authority, mutation, migration or privilege.

`createTripInventoryReader(client, authenticated, readCanonicalTrip)` returns `readInventory(signal?)`, bound by Main as `getTripInventory`. The return is the existing `{data}|{error: FailureCode}` union. Main wiring: import the factory in `user-data-adapter.ts`, bind with `(credentials.client, authenticated, operations.getTrip)` and expose `getTripInventory` only from `createNativeTripDataAdapter`. Existing list/read behavior stays intact.

`GET /api/trips/native/v2/inventory` accepts no query, Cookie, Origin or body; the handler uses existing Native runtime trip configuration, request scope (10 seconds), identity adapter and before/after identity checks. Success uses private/no-store; failures contain only the existing error code, with no partial Trip collection. Main owns route and adapter wiring, implementation owner owns `lib/server/trip/inventory/**`.

The closed success DTO is `{schemaVersion:'native-trip-inventory/1', ownerId, coverage:'owner-visible-canonical-trips', complete:true, count, trips, digest}`. Trips are sorted strictly by ID, each `{id,headVersion,title,updatedAt,content:{days},confirmationState}`. Content is the existing canonical projection, including valid version-zero/empty-days state and original confirmation semantics. No audits, history, external/raw snapshots or inferred confirmation. Digest is SHA256 of recursively key-sorted JSON of `{schemaVersion,coverage,ownerId,count,trips}`; array order is retained. Entire success is at most 262144 UTF8 bytes.

Read exact count and ID-ordered headers with limit 9; count must be an integer 0–8 and equal the returned row count. Null count/data, excess rows, duplicates, unordered/invalid headers and missing pages fail closed. For every header read original canonical `getTrip`, require the identical ID/version/title/updatedAt tuple and validate closed content. Reread headers/count and require an identical tuple set, then recheck original identity. Errors, unreadable canonical state, change, overflow or deadline do not produce `complete`. Exact zero requires two successful count-zero array reads and identity recheck; null never means zero.

This is an **optimistic stable-head owner-visible canonical snapshot**, not a database-wide, physical-row, historical or RLS-hidden inventory. It detects monotonic head/tuple and set changes visible at the observation boundaries. It cannot prove absence of transient create/delete between reads, or privileged backup/rollback that restores the same tuple. Archived/inaccessible state follows original RLS/getTrip; an unreadable visible header fails the whole observation, never gains privileges.

Harness acquisition requires an explicit allowed HTTPS origin and authorized Native fetch (no default fetch or credential discovery). It observes session owner/session/mobileEpoch around each inventory read, validates DTO/digest and finite body, and invokes the existing `runRuntimeAsk` only after a complete before snapshot. It retains original submission IDs/key and performs no mutation retry. A shared monotonic lifetime and request/byte budgets cover before, Ask and after, capped at the existing 20s/64 requests/1MiB. Any missing before causes NOT_RUN/zero submit; uncertainty never becomes unchanged. Only metadata/digests are reportable; raw Trip content stays in memory.

Controlled transport and recorded JSON prove parser/behavior only. No HTTP shape, caller mode or label attests source, usage, attempts or model consumption. `requiredModeVerdict` and `finalAcceptance` remain NOT_RUN. This port does not close H1–H5 or #264, grant runtime consent or authorize a real H04/provider run.
