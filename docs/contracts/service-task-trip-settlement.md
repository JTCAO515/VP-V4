# Trip ServiceTask development settlement

Related to [AGENT-008 #227](https://github.com/JTCAO515/VP-V4/issues/227). This is an incomplete development slice, not billing enablement or full Issue closure. The original [ServiceTask contract](service-task-metering.md) remains authoritative.

The append-only migration `20261015055708_agent008_trip_service_task_settlement_current.sql` adds a nullable `service_tasks.trip_objective` reference record. A new task is born as `trip_modification`; existing text/reviewed tasks cannot convert. It records canonical conversation/goal/current message, exact confirmed goal-to-Trip link and version, scoped context, operation digest, immutable Proposal revision/digest and the original worker binding. It copies no conversation body or Trip content. The existing canonical message receives its one-time Task link, so existing lifecycle graph traversal can find the Task.

`trip_enabled=false` is the independent default admission gate. Original capacity `enabled=false` remains record-only. When explicitly enabled in an isolated development fixture, the original Free/Pass snapshot and account lock reserve the original capacity ledger; existing attempt budget/cost accounting remains separate. No real environment is enabled.

The existing Web/native scoped-edit routes accept explicit `schemaVersion: "trip-service-task/1"` requests:

- `trip_context`: `goal` is the exact canonical source tuple; `context` is the original closed context request. The Trip-only owner bridge validates current owner/session/consent/link.
- `trip_task`: `operationId`, original `basis`, `text`, and `goal` admit the new objective once. Same key/content replays; different content conflicts. Another key cannot create a second task for that same goal.
- `trip_select`: `selection` is the original closed candidate-selection request. The existing selector validates original settled attempt/completion and creates the original Proposal with its visible diff.
- `trip_read`: `operationId` reads the original operation. Unknown acknowledgement never causes automatic resubmission, replacement work, selection or confirmation.

`goal` contains `conversationId`, `goalId`, `goalVersion`, `messageId`, `messageSequence`, `linkVersion`, and `linkOperationId`. Callers obtain these through existing canonical goal/message and explicit goal-to-Trip link interfaces. Supplying IDs alone grants no authority. No end-user UI has been added in this slice.

`trip_service_task_owner_v1` exposes only qualified Trip context/selection/read/cancel. `trip_service_task_worker_v1` exposes a closed method/argument set for qualified Trip work; its claimer filters the original queue before leasing. Legacy scoped RPCs and all private functions retain their revoked ACLs. `tripTaskWorkerRPC` composes the new bridge with the original executor's injected RPC port; hosted worker entrypoint integration remains outstanding.

The original `confirm_and_apply_trip_proposal` retains exact confirmation digest, owner/session, original Patch, version conflict, scoped-source guards, snapshot and idempotency checks. Its entry hook acquires the original account capacity/grant lock before Proposal locks. The immediate original Trip-event trigger validates the producer binding, completed Turn, current source/consent and readable new snapshot and settles the already reserved task once in the same transaction. An error rolls back Trip, snapshot, event and capacity together. Record-only tasks retain business outcome without acquiring capacity. Manual unassociated proposals do not enter this ledger.

Rejection/expiry/conflict release only pending reservations. `cancel_trip_service_task_v1` returns `committed` after application; it does not undo the Trip or settlement. Original text admission/completion cannot reinterpret a Trip task. Provider usage/cost remains the original attempt authority; missing accounting is never synthesized as zero.

## Remaining gates

The new reference column is registered in the exact conversation/Turn source schemas and export decoder. Seven fixed source/schema/runtime definitions are versioned with original and resulting source hashes, exact column/constraint and trigger deltas; unknown changes remain denied. Infrastructure and existing write-hook guards remain unchanged. The original runtime guard fingerprints whole function definitions, so registration updates those exact fingerprints rather than adopting observed catalog state.

Deletion facts reduce the reference to `trip-service-task-erased/1`, an inert goal identity and optional Proposal identity. They prevent a deleted goal resetting its budget and a late Proposal reverting to an unassociated manual confirmation. Message/conversation/Trip IDs, context/request digests and producer binding are removed. The task type remains unchanged and the field remains nonnull. Hidden root text, actual canonical message deletion, the original Trip tombstone, and actual account deletion trigger this reduction; only original deletion facts permit it. Reserved capacity is released before scope removal; settled history is retained. An original account deletion can still be blocked by the pre-existing `model_budget_scopes_owner_id_fkey`; this is preserved as a failed-transaction rollback test, not a successful account purge.

The original v1 privacy source/count DTOs retain their original shape. The explicit `privacy_trip_service_task_v1` selects `conversation-trip-data/1` or `turn-trip-data/1`; it reuses the original owner/session/epoch, source/consent, preview, exact-byte confirmation/recovery, transaction proofs and operation tables. Its registered scoped contexts/work/requests/operations/lineage are erasable only when the new Trip Task and context are exclusively proved. Legacy manual and shared context remain blockers. Five additional erased-source counters and `tripObjectives` redaction are visible only in this version. The source schema carries this version explicitly; unknown versions are rejected.

Real local preview→confirmed erase→exact-byte recovery and strict TS decoding pass for both conversation and single-Turn scopes, leaving Trip content and independent attempt costs unchanged. Narrower Turn erasure that would affect another Turn/shared context remains blocked. Original v1 refuses a versioned operation instead of returning its additional counters as a v1 DTO. Original D2 source dispatch/page now selects the strict Trip export version only for its five registered sources. The existing TS handler and commit-qualification check pass in the original explicitly enrolled C0 local-policy fixture; no real artifact/key or permission enablement is proved. The original immutable privacy operations also retain exact PK fences for the five Trip sources; both conversation and Turn restore attempts are rejected rather than rehydrating erased copies. Real dual-transaction completion/cancel and continuation-selection barriers, mixed text/Trip last capacity, grant revoke/expiry, strict v1/v2 mixed receipts, and the original immutable Proposal wall-clock expiry have local evidence. The baseline account budget cleanup limitation remains explicit; real backup/restore acceptance is not established. This slice remains not merge-ready.

The explicit hosted profile `vpj10-hosted-trip-service-task/1` and independent `VISEPANDA_HOSTED_TRIP_SERVICE_TASK_WORKER=true` opt-in are wired into the original CLI, loop, queue, transport and tariff checks. Legacy/new profile mismatch, both mode flags, invalid flags and absent Trip opt-in fail before any dispatch. No hosted target is started by this migration or by normal API requests.

The versioned producer can persist a necessary `clarification` only with a settled original attempt. `trip_continue` binds `taskId`, latest `parentTurnId`, `operationId`, relationship `clarification` or `repair`, and the current input text. It creates a new Turn in the same Task and fixed budget scope, preserving the same capacity reservation. Existing current-input consent is respected: prior dialogue is not automatically added to a provider request; the submitted continuation must contain the current instructions needed by the original selected scope. A valid known-cost technical failure can be recorded without another provider call, then repaired on the same Task. Unknown dispatch/usage cannot authorize repair. Completion, output publication and Trip confirmation still require current source/lease authority; financial metadata reconciliation is separate. Same-goal replacement admission and old-text continuation remain rejected, preventing budget resets. Partial billing, revisions after delivery, waiting TTL and cross-period policies remain gated. Actual UI, remaining lifecycle/export/expiry/grant/deletion race checks, target Auth, real provider costs, formal exact-head review and CI remain separate outstanding work. The parent Issue stays open.

Local tests use private PostgreSQL 17.11 with no TCP listener, private Unix socket and synthetic SQL auth/session fixtures. They are C0 role/transaction evidence, not signed GoTrue authentication, PostgreSQL 17.6 target compatibility, shared-database migration or production acceptance.
