# Conversation Task state reader / v1

VPJ-81 #562 bounded read slice. GET `/api/chat/native/v5/conversations/{conversationId}/tasks`, optional single `cursor` (base64url JSON, at most512 characters). Fixed page limit20; no caller Task IDs, owner IDs, policy override or limit. Authenticated read-only RPC `list_assistant_conversation_tasks_v1(policy, conversation, cursor)` derives current owner/mobile session and checks current conversation policy and matching non-revoked consent. Producer-off authorised reads remain available through the base text gate. Old owner-20 APIs remain unchanged.

## Membership and status

Consider Task-bearing messages across the entire selected conversation, including beyond the50-message transcript. Only the latest association for each Task qualifies. The source must be an owner/current-policy/current-consent follow_up or amendment with a real owner goal in the same conversation. Task policy/consent, visible root and exact canonical last_turn_id, active owned thread and matching service_task_turns linkage must qualify. A hidden/missing/revoked/invalid latest Turn cannot fall back to an older completed Turn. Goal/source and Task scope versions remain distinct.

Wire version5 kind conversation_tasks returns conversationId, conversationSequence, limit20, paired messages/turns, nextCursor. Messages contain actual120-character association excerpts and IDs, without a Task input/output body. Turns contain only canonical Turn/Task IDs, scopeVersion, relationship/parentTurnId, status/outcome, association goalScopeVersion and its currentGoalScopeVersion. Native validates paired Task IDs/goal basis, unique membership and canonical relationship/status; it shares the existing projection logic with the unchanged native Turn model. Completed is the actual execution status; a changed associated goal disables its result action and is labelled as needing recheck. Opening reuses the existing Task-directed exact resolver and content reader; no result availability is inferred from completed alone. Cancellation reuses the existing canonical Turn endpoint.

## Bounds and cursor

Two additive partial indexes bound the conversation Task-association sequence window and latest-association lookup. Examine at most128 raw Task-bearing associations plus one overflow sentinel, qualify current latest memberships, and require a21st qualified Task before issuing a20-row continuation. Sparse/raw overflow returns unavailable with no partial metadata or hidden-row cursor. Non-Task messages are not candidates. Cursor contains exactly version1, conversationId, conversationSequence and last returned messageId; the RPC validates the current owner/conversation/policy/consent/latest readable anchor, not proof of prior delivery. Membership changes invalidate the cursor. Task status is re-read per returned canonical row; pages do not claim an atomic whole-Task-set snapshot or total count.

Native pages replace rather than accumulate cached Task state. Ordinary polling retains the current cursor while membership version matches; a membership change or mutation readback starts at the first page. First-page return is explicit. Account/selection/refresh generations fence late page replies. A missing/unavailable page remains unknown; it never means all work completed. State/body/transcript lifetimes remain separate.

No new writer, provider, worker, queue, permission grant to tables, paid action, translation/history change, Journeys or privacy/export change. Applied migration060000 is additive. Real target/provider/device/full-ticket acceptance is not established by this contract.
