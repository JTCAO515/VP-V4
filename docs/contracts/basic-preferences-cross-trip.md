# 基础明确偏好跨 Trip

**Owner：**VPJ-11 #199；协作 #190（数据政策）、#195（真实 Ask）、#206（有依据回答）。
**依据：**[品牌蒸馏 Q36](https://github.com/JTCAO515/VP-V4/blob/8ae95a7/docs/brand/VISEPANDA-BRAND-DISTILLATION-Q1-Q38-2026-09-10.md#q36--免费用户的基础长期偏好能否跨规划使用)、[代码与研究证据](../research/brand-engineering-2026-09-10/memory-evidence.md)。

## 用户结果与权限边界

Free 与 Journey Pass 均可保存、查看、纠正、暂停、撤回及使用用户明确授权的基础长期偏好；创建下一 Trip、再次登录或 Pass 到期，不应仅因免费身份而遗忘这些偏好。此共同权益不表示无限生成、无限历史综合、自动画像或新增数据接收方权限。

偏好需要在有关建议中产生正确影响，无需每轮声称“我记得你”。用户可以仅本次使用、不保存、仅当前 Trip 保存或明确跨 Trip 使用。不保存不妨碍在当前任务中按已授权输入提供帮助；本次不用不等同于永久删除。

实际保存期限、处理地域、模型接收方、敏感信息及删除/备份规则由 #190 明确；该规划不自动开放尚未获准的数据路径。当前运行 API、数据库 schema 和模型消费者能力仍以实际实现与验证为准。

## 唯一权威源与最小数据

沿用现有 Profile、Trip、Memory、working context 和来源/消费收据体系。Profile 已有的旅行节奏、单位等字段保持原权威来源，不复制为另一份可独立编辑的 Memory 事实；任务投影引用其受控版本。Trip 事实仍在 Trip；临时输入留 working context；明确保存且没有既有权威字段的长期偏好沿用 Memory。不得为本需求另建第三套 Preference 存储或隐式画像库。

实现阶段需对以下**候选**字段作最小化设计、接口版本化和迁移验证；它们不表示当前 schema 已支持：

| 信息 | 最小语义 |
| --- | --- |
| 标识与来源 | 沿用 owner、record ID、source receipt；必要的语义 key 用于同类偏好消歧 |
| 内容 | 有界明确偏好及 preference/hard constraint 区分；不得把推断自动提升为硬约束 |
| 范围 | 当前 Trip 或账号跨 Trip；Trip 范围绑定正确 Trip；仅本次不新增永久记录 |
| 同意与状态 | 授权内容/用途/范围可追溯，状态区分可用、暂停、撤回、删除等既有语义 |
| 版本 | 单调 revision 或等价并发控制；消费依据能够识别实际读取的来源版本 |
| 期限 | 有明确时效才设置 validUntil；未知期限不等于永久适用 |
| 相关性 | 服务端按当前任务决定使用资格；无需持久保存笼统人格评分或模型置信画像 |

当前管理 API 可返回暂停、撤回或其他不可供模型使用的记录，以支持用户控制；其结果不得整体作为模型输入。Profile 的管理展示默认值也不能自动视为用户明确表达的偏好。

## 保存、冲突与任务投影

用户已明确说“记住”，且内容、保存用途和范围授权清楚时，可以按该授权保存，不要求形式化地再确认一次。内容或“这次/长期”范围不清、模型推断或敏感属性推测，只能形成待澄清候选；不得自动写入长期画像。明确的当次饮食限制也不授权推断健康或宗教身份。

对**同一偏好维度**，当前明确输入优先于当前 Trip 范围偏好，再优先于明确长期偏好。这不改变已确认 Trip 事实、权限和安全规则；有安全意义的历史硬约束与当前含糊要求冲突时，需要澄清。建议涉及更改已确认行程时仍必须走 TripProposal/diff/确认。

模型调用前，由既有服务端链路生成 task-specific projection：核验当前 actor、同意/用途、状态、scope/Trip、最新版本、有效期、本次禁用和任务相关性，再按 ContextPlan 允许来源与预算装配。问答或恢复需要某项偏好时，须显式版本化其允许策略，不能无条件把所有记忆灌入上下文。个人偏好是数据，不提供指令权限，也不能证明外部地点营业、安全或库存等事实。

消费收据只关联实际入选的来源与版本；区分“输入上下文”与“实际支持回答/提案”，不得把检索候选、被预算丢弃的记录或仅有收据类型当作品牌能力证据。来源信息保留必要标识，日志不复制偏好全文或敏感内容。

## 纠正、撤回与异步一致性

- 纠正应原子更新或替代明确来源并比较版本，两个设备冲突不能静默覆盖；后续使用立即以新版本为准，不要求用户改完设置再纠正模型。
- 暂停、撤回或删除后，新的模型发送不得使用旧值；队列、重试、上下文压缩及派生缓存按来源/版本失效，重新装配时再核验。仅本次不用限于相应任务，不误删长期偏好。
- 在途生成或待提交提案的依据失效后，不得继续把旧结果作为当前有效建议或自动提交。必要时取消或重新生成，并诚实说明处理状态。
- 已发送给获准外部处理方的数据不能假称“撤回发送”。记录真实边界，后续保留/删除按 #190 的实际政策与可验证结果执行；申请删除不等于删除完成。
- 登出、换账号与共享设备切换时清理该账号的本地展示/任务缓存并使身份 epoch 失效。A 的迟到响应不得进入 B 的页面、任务或来源收据；在授权检查前不复用账号缓存。
- 删除偏好后，其派生摘要和后续任务不能复活旧内容。已确认 Trip 和历史交付不通过偏好删除接口悄悄改写；历史内容、来源收据、导出、备份恢复及其删除结果按既有隐私合同分别处理，不承诺无法证明的即时全局抹除。

## 写入成功轻提示（2026-09-11）

已确认的首版交互：沿用现有记忆写入逻辑，新增保存成功后的轻提示；不改变记什么、保存条件、范围或权限，不为提示增加模型调用。

- 记忆新增或更新实际成功后，在当前操作的页面顶部显示“已加入记忆”／“Saved to memory”，唯一按钮为“撤销”／“Undo”；第一版不加“查看”。
- 默认4秒自动隐藏，不阻断输入或抢焦点。有现成且允许展示的简短摘要可附一行，没有就只显示成功文案；不额外生成摘要。读取/回放/后台同步本身不触发提示。
- 撤销绑定这次成功变更及其版本：真正撤回新增项，或安全恢复本次更新前的值；不覆盖之后的新修改，不改Trip或其他记忆。撤销成功显示“已撤销”／“Undone”，失败或版本冲突保留真实状态并提示重试/核对。撤销自身不再触发“已加入记忆”。
- 同一逻辑写入的重试、重连与事件重放只提示一次；未写入、失败或结果未知不显示成功。登出或换账号清除旧账号提示和操作入口。
- 提示消失不影响已保存记忆；原有记忆管理入口保留。键盘焦点/交互期间不强制移除正在操作的按钮，用户离开提示后继续自动收起；不引入独立计时权益或新记忆历史系统。

本增量归#199实现和验收：验证真实新增/更新成功、4秒收起、撤销成功/失败/版本冲突、重复事件及换账号；前端fixture只证明展示，不证明真实写入/撤销完成。正式方案不扩大当前数据授权或原生/Web范围。
