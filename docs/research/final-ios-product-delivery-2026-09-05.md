## 1. 推荐结论与本轮真正修订

VP 的完整产品是一个围绕同一 Trip 连续工作的原生 iOS 旅行助手。规划员、准备检查员、导游、翻译员、讲解员和恢复协调员共享一个 VP 身份、一份经用户控制的旅程状态。用户可以从任意旅行时刻进入，得到适合当前工作的界面和下一动作。

`Plan / Ready / Travel` 用于组织能力与验收，不是限制只能服务三个片段。前面的灵感探索、第三方预订衔接，以及后面的复盘、归档、分享和下一次旅行，都属于完整旅程。三个阶段也不构成强制步骤：已经在路上的人应直接使用翻译或问路，已经订好行程的人应直接导入检查。

最终导航采用已讨论的 **Trip · Explore · Ask · Tools · Profile，默认 Ask**。`Today` 是 Trip 内的当日视图；Guide、翻译、酒店、准备等按上下文出现，不为内部 Agent 角色另建 Tab。9 月 3 日研究中的三 Tab 是备选，9 月 4 日已回到五 Tab；原生壳里的 Today 顶层页需要迁移。此前图像生成器额外画出的 Saved、Me 等不作为产品需求。

Web 保留精简 Planning Studio：同 Trip 的 Chat、浏览、基本结构编辑、Proposal 差异确认、最新状态与账号权益；iOS 提供全部首发能力。保留已有有效 Web 编辑和确认路径，避免再次建完整桌面编辑器。现场翻译、导览播放、系统分享导入、离线包和设备通知以 iOS 为主。

中英成为本阶段唯一质量承诺。西/俄/阿从首发矩阵移出，保留未来可迁移的数据能力。中英涉及 UI、错误/降级、知识、语音、运营文案、付费、商店页、邮件和支持，不只是将语言选择器减少到两个选项。

主动陪伴首发应包括 App 内明确的 Next Step、回来后接续、用户主动设置的确定时间提醒，以及已被接受服务任务的真实进展通知。持续定位、无事实触发的闲聊、Live Activity 和复杂情绪角色后置。这样既保留有温度的陪伴，也让每次主动出现都有用途。

## 5. Chat + Plan 的最终交互结构

### 5.1 一个 Trip，两种工作呈现，避免多层导航堆叠

Ask 中的首轮结果是简短解释和可操作成果卡。卡片上的“查看计划”打开同一 Trip 的全宽编辑视图。Trip 内的“问 VP”以当前对象为范围呼出助手；需要深聊时进入 Ask，但保持 Trip/选区标签和明确返回位置。不要在五 Tab 之上再永久叠加 Discuss/Plan/Today/Ready 四个横向栏。

概念层仍是 Discuss/Plan 两种视角；具体交互采用“主页面+就地助手+原位置返回”，而不是三个独立产品。切换保存输入草稿、滚动锚点、选中对象和用户正在比较的分支。

```text
Trip · Explore · Ask · Tools · Profile
                       │
                 当前 Trip + 简短接续
                       │
              对话 + 一份主要成果卡
                       │ 查看计划
                 Trip 全宽 Day 列表
                       │ 选两项 → 问 VP
                带对象范围的助手 Sheet
                       │ 查看改动
           Before / After / Why / Impact
                       │ 明确确认 + 服务端回执
                回到同一天、同一位置
```

### 5.2 手机规划器的能力底线

- 总览显示城市段、相对/实际日期、关键固定点和未决事项；某日显示顺序与区域，不把一周缩成细小网格。
- 支持直接增删、改时、移到某日、重新排序、备注和显式锁定；拖拽有“上移/下移/移到”按钮替代。
- 日期未知时使用 Day 1/Day 2，不猜公历日期。修改时区、航班到达和日期后重新检查受影响关系。
- 直接手改先保存草稿；已确认安排的改变仍进入 Proposal/可见 diff/确认路径。语音或 AI 不是基本编辑的必要条件。
- “只调整下午，晚饭保留”绑定选中的对象和版本；用户切换 Trip/分支/选区后，旧结果留在旧任务。
- 比较页显示变化前后、原因和影响；小屏优先纵向呈现。部分采纳要重查关联约束，不能直接拼接互相依赖的片段。
- 确认时锁定审批对象。成功提示以服务器回执为依据；断网时保留 pending/unknown 并查询，不重复提交。
- 历史聊天卡标明生成版本，提供“打开当前版本”；不让旧卡偷偷变成今天的计划。

### 5.3 一条回答的默认结构

1. 一段足够短的自然回应，先说明结果或取舍。
2. 一份主成果：方向比较/地点候选/局部计划/翻译/解释/未知路径之一。
3. 对当前决定有意义的依据与未知，可展开查看细节。
4. 一个主要动作、最多少量次动作。
5. 可选的 1–2 个澄清选项；全部可跳过，只有真实人工或外部执行缺必要字段时才要求补齐。

`Shape your idea` 可以作为不打断的可选微入口，但不在每条回复后机械附上问卷。显著改口、日期冲突、跨 Trip 记忆适用不明时才主动澄清。反馈入口应贴近具体回答或改动，而不是用户每次完成一件事都弹满意度调查。

| S28 | 付费/权益 | 查看范围、购买、恢复、管理 | pending/取消/成功待同步/退款/账号不符 | UI 成功与服务端权益一致 |
| S29 | 通知设置 | 每 Trip/类别开关、静音 | 系统拒绝/用户关闭/时区改变 | 关闭即时影响后续派发 |
| S30 | 离线资料 | 下载、查看版本、清除 | 未下载/部分/过期/不可离线/失权 | 静态资料不冒充实时服务 |
| S31 | 社区提交 | 草稿、预览、提交、撤回 | 审核中/退回/发布/下架 | 不把“提交成功”写成“已公开” |
| S32 | 举报/屏蔽 | 举报内容、屏蔽作者 | 已提交/重复/处理反馈 | 社区第一版可实际处理问题 |
| S33 | 轻量分享 | 选模板、删私密字段、系统分享 | 本地生成/导出失败/私密预览 | 默认为不含订单号/住址细节 |
| S34 | 旅程结束 | 归档、复盘、选记忆 | 已归档/服务未完/未确认偏好 | 服务任务不随 Trip 归档消失 |
| S35 | Web Planning Studio | Chat、基本编辑、diff 确认 | 跨端新版本/旧 Proposal/独立 Web 会话 | 不出现第二份 Trip 真相 |

S31–S33 承接已有 Community 与简单分享模板方向；关注、私信、复杂社交关系、视频生成和完整 Creator Studio 为后续阶段。若主报告将其拆为后续上线批次，应标为排期后移，而不是当作无用内容直接删除。

## 7. 陪伴如何成为产品行为

### 7.1 四种记忆、四种不同界面控制

| 记忆 | 例子 | 用户看见什么 | 使用与修正 |
| --- | --- | --- | --- |
| 当前工作状态 | 正在比较 Day 3 下午两个活动 | “上次比较到这里”+对象链接 | 自动接续，关闭页面不丢；换 Trip 隔离 |
| Trip 事实/明确约束 | 酒店地址、这趟不换住宿、不能移晚饭 | Trip 信息/约束 chip | 用户改事实后撤销旧依赖 |
| 长期明确偏好 | 喜欢慢节奏、回答简短 | Memory 卡和适用范围 | 可查看/纠正/删除/仅本次 |
| 推断偏好 | 多次看低价住宿 | “最近更偏向低预算；这次仍然如此吗？” | 低置信、可过期；不变成永久身份或隐藏的硬约束 |

预算倾向与沟通语气可以帮助排序和表达，但不要推断情绪诊断、收入水平、人格或脆弱程度。角色始终是 VP；专业温度主要体现为记住已确认细节、保护用户已有安排、解释取舍和允许不同意。

本轮最终商品采用 Free/Journey Pass；旧 Plus 月订阅为后续候选。Profile 应允许用户查看和纠正已存文字；是否让模型跨 Trip 读取不能只用前端开关实现。没有 Pass 时，当前 Trip 必要上下文仍应服务基本任务，不能反复询问制造付费痛点。

### 7.2 何时主动开口

| 级别 | 触发 | 默认呈现 | 首发处置 |
| --- | --- | --- | --- |
| P0 接续 | 用户主动打开 App/Trip，已有未完任务 | 一条短接续+可直接继续 | 必须；不播放语音、不弹强模态 |
| P1 操作相关 | 用户改日期，影响既有安排；Proposal过期 | 当前工作面具体提示 | 必须；说明影响对象，允许稍后 |
| P2 用户设置 | 明确时间的准备/出发提醒 | App 内；用户授权后本地/远程通知 | 首发有限支持；绑定时区和 Trip |
| P3 真实事件 | 已接受人工任务更新；获准来源变化影响 Trip | App 内消息；类别授权后 Push | 对有可靠事件能力的路径开放 |
| P4 推测机会 | 系统推测用户无聊/焦虑；附近推荐 | 未证明净收益前不主动打断 | 后续实验，不进首发依赖 |
| P5 持续陪聊 | 持续监听、自动发言、关系维护 | 不采用 | 与专业旅行伴随定位不符 |

一个通知候选须有 reason、相关 Trip/object、有效期、用户偏好、去重键、最后事实核验时间。临近触发再次检查 Trip 是否已改、用户是否已处理、通知是否过时；用户关闭后撤销排队发送。重要通知可用系统能力提升可见性，但不能把通知一定送达写成服务保证。

### 7.3 把诚实降级变成可感知能力

| 内部原因 | 可用中英话术示例 | 有用动作 |
| --- | --- | --- |
| 没有当前营业依据 | “我还不能确认它今天是否开放。你原来的安排先保留；可以先看官方信息，或比较附近备选。” / “I can’t confirm today’s opening hours yet. I’ll keep your plan as it is; you can check the official page or compare a nearby alternative.” | 官方入口、备选，不擅自改计划 |
| 服务商超时 | “这次没取到最新路线。已保存的地址还在；你可以先打开地图，我也可以再试一次。” / “I couldn’t get a fresh route this time. Your saved address is still here; open it in Maps or try again.” | 保存地址、实际地图出口、重试 |
| 用户资料不够 | “我可以先比较区域。要查看与你实际入住条件相符的房间，还需要日期和入住信息。” / “I can compare areas now. To check room options for your stay, I’ll need dates and occupancy details.” | 跳过继续探索，执行时补必要信息 |
| AI 配额已用完 | “这轮 AI 额度已用完，恢复时间是…；你的行程仍可查看和手动调整。” / “You’ve used this window’s AI allowance. It resets at …; your trip is still available to view and edit.” | 手工编辑、资料、权益页；不锁已有成果 |
| 人工未接受 | “请求已收到，还没有人接手。我会在有人接受后显示负责人；你也可以先用下面的自助路径。” / “Your request is received, but no one has accepted it yet. The assignee will appear once it’s picked up; here’s a self-service option meanwhile.” | 实际状态、自助、撤回 |
| 低确定翻译 | “这句话有两种可能含义，先别直接用它确认金额。我把两种说法放在下面。” / “This could mean two different things. Don’t use it to confirm the amount yet; here are both readings.” | 原文/转写纠正、澄清短语 |

语言是结果状态的呈现层。不能为了温暖把“未查到”改成“我已经帮你确认”，或把系统故障一律包装成“我需要更多信息”。未知卡需要被解决、被替代或被用户知情跳过；只有前述操作减少风险/减少重复劳动，才形成信任资产。

## 8. 视觉系统：温暖、清楚、适合户外

品牌根 token 继续来自 `brand/tokens/visepanda.tokens.json`。SwiftUI 使用系统语义字体与平台材质；Web 保留自身组件实现，通过同一语义 token 对齐品牌，不共享 React 视图或把 px 原样搬成全部 iOS 尺寸。

| 语义 | 建议值/处理 | 适用 |
| --- | --- | --- |
| 背景 | Cream `#FFFDF4`，大数据/地图区域保持简洁 | 默认浅色主题 |
| 文字 | Ink `#120807`；次文字用满足对比的中性色 | 正文、金额、来源、关键状态 |
| 主要品牌 | Plum `#732E4B` | 主要按钮、选中态、少量标题 |
| 发现/强调 | Gold `#FFAB48` 配深色文字 | Explore、选区强调，不作浅背景上的关键小字 |
| 深 Gold | `#8B681F` | 需要金色文本时的候选，实际对比另测 |
| 正文 | 系统 `.body`，默认约17pt，随 Dynamic Type | Chat、计划、译文 |
| 关键辅助 | `.subheadline`/`.footnote` 按语义 | 关键状态不可仅靠11pt脚注 |
| 标题 | 系统22–28pt级别；大标题只在入口 | 避免编辑时巨大装饰标题 |
| 间距 | 4/8/12/16/24/32pt；水平16–20pt起点 | 组件密度随大字适配 |
| 触摸目标 | VP 自定≥44pt，主要动作48–56pt | 在途、单手；不混淆视觉图标尺寸和hit area |
| 圆角 | 控件12–16pt、主要卡16–24pt；系统sheet用系统形状 | 避免所有元素巨大胶囊 |
| 图像 | Explore较丰富；Trip编辑/确认少量 | 来源/许可可追溯，低网速延迟加载 |
| 熊猫 | 小头像、状态姿态、空态说明 | 固定VP识别；不遮住资料/关键动作 |
| 材质 | 导航/短时操作层用系统材料；正文不透明为主 | iOS26+可渐进Glass；17保持同任务能力 |
| 深色 | 单独语义调色与对比验收 | 不简单颜色反转；地图/图像/字幕一起测试 |

科技感通过“对象之间连接明确、任务可以恢复、变化可感知、延迟可解释”表现。全屏发光、持续粒子、每条回复弹跳和大块磨砂无法提高这些能力，还会抢占旅行时的视觉注意力。

界面必须在阳光下、低亮度、大字体、Reduce Transparency、Increase Contrast、VoiceOver 中实测。此前 token 纯色计算不等于本次实际界面过关；使用 [Apple Accessibility 测试指引](https://developer.apple.com/documentation/accessibility/testing-system-accessibility-features-in-your-app) 验证最终合成后的状态。

## 9. 动效、手势与反馈合同

下列时长是初始设计参数，系统原生转场优先，真实设备再调。动效的完成不能驱动业务成功。

| 场景 | 动效/反馈 | 中断与Reduced Motion |
| --- | --- | --- |
| 点击 | 约100–150ms高亮或0.98轻压缩 | 松手取消；减少动态时只高亮 |
| 选择计划对象 | 即时边界+文本数量，可轻触觉一次 | 颜色不是唯一依据 |
| 呼出对象 Ask | 原生sheet，约220–320ms系统级响应起点 | 可拖回；关闭保存输入；大字/键盘时升为大高度 |
| 查看计划 | 原生push/视角转换，约180–260ms | 返回保持原滚动位置，不旋转整个页面 |
| 流式回答 | 语义块稳定出现 | 不逐token动效；用户读历史时停止跟底 |
| 局部diff | 同对象Before/After明确对应，轻淡入 | Reduced Motion显示文字差异 |
| 已保存 | 回执后局部约180–250ms强调+状态更新 | 失败不给成功触觉，pending可继续查看 |
| 拖拽排序 | 跟手、临位、邻项让位、短spring落位 | 拖拽可取消；按钮重排等效 |
| 地图 | 用户选点时轻量定位关联 | 不随着每段AI文本自动飞地图 |
| 语音 | 波形反映真实输入，播放反映实际进度 | 无音频不做假波形；文本等效 |
| 等待 | 真实阶段、可取消/离开 | 不造百分比和假的“多个Agent正在协商” |
| 熊猫 | 欢迎/低风险完成时少量点头 | 静态替代；不循环吸引注意 |

三处必须用原生交互录像评审：sheet拖动与内容滚动的手势归属；流式回包与键盘/选区保持；确认后断网重连与pending恢复。iOS 17用标准导航/材料，较新OS只增加视觉增强，不让旧设备少掉任何核心任务。[Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)、[Apple Springs](https://developer.apple.com/videos/play/wwdc2023/10158/)、[Apple PresentationDetent](https://developer.apple.com/documentation/swiftui/presentationdetent)

## 10. 原生架构与需要冻结的接缝

### 10.1 最小充分结构

```text
App / Navigation / Session
  ├─ Ask / Trip / Explore / Tools / Profile
  ├─ 受控原生卡片 + ProposalReview + SourceView
  ├─ Feature-local状态 + 注入的Repository
  ├─ URLSession transport / 事件归约 / 任务恢复
  ├─ 本地草稿与获准快照 / 材料待处理队列
  └─ PhotosPicker / Share Extension / 音频 / 定位 / StoreKit / 通知
                         │
                 版本化Native API
                         │
                同一服务端领域服务
                         │
             Web适配器继续使用Cookie/CSRF
```

本地值状态使用 `@State/@Binding`；真正跨页的服务使用 Observation/注入。不要为每个小卡片建立全局 ViewModel；不让一个聊天 token 重绘整份计划和地图。耗时解析/大文本格式化离开主线程，UI更新在正确隔离域完成。

### 10.2 状态与数据所有权

| 状态 | 谁拥有 | 不变量 |
| --- | --- | --- |
| 导航、焦点、选区、滚动 | 当前客户端 | 保存轻量ID；账号切换清除用户相关导航 |
| WorkingDraft | 当前编辑会话；同步后由服务端有版本记录 | `draftId/revision/baseTripVersion` 不省略 |
| 已确认 Trip | 服务端领域服务 | CAS/幂等/权限/审计，客户端不能直写 |
| Proposal | 服务端不可变候选或明确子修订 | 审批绑定用户实际看见的版本 |
| Conversation | 获准留存服务 | 交互历史不是当前Trip权威 |
| Task/Turn | 服务端任务生命周期 | App退出不等于取消；重复流不重复应用 |
| 外部预订 | 来源明确的外部观察/用户凭证 | 外跳、导入、核实与成交分开 |
| 记忆/资料权限 | 服务端当前授权；本地按可用范围缓存 | 撤回、删除、账号变化影响读取与派生 |
| 权益/用量 | 服务端验证及计量账本 | 前端按钮和本地时钟不授予权益 |

展示合同只允许已编译组件类型。至少有 `schemaVersion/taskId/turnId/subjectScope/objectRefs/basisVersion/contentParts/actions/evidenceRefs/deliveryState`，复用已有领域对象，避免重新命名和复制整个后端模型。服务端输出文字里的“已确认”不作为业务状态；卡片状态来自对象回执。

原生 API 与 Web API 可以调用相同领域服务，但认证适配不可混用：原生校验Bearer、用户、token时效、安装/会话代次；Web保留Cookie与CSRF。不能给原生请求伪造Origin，也不能为兼容App删除同源保护。

### 10.3 手机单安装与Web并发

新手机完整认证成功后，由服务端推进安装代次并撤销旧安装的新请求权限；Web会话独立、不做IP/指纹限制。旧设备离线时无法瞬间获知撤销，不能承诺远程立即擦除已缓存内容；回网/续约时停止读取、清除授权缓存。紧急离线地址和公开短语可按数据分级保留，其余按明确策略处理。

### 10.4 系统分享、照片和媒体

PhotosPicker优先于全照片库访问。Share Extension收件时明确文件、Trip去向和上传选择，轻量校验后写App Group待处理区，由主App/服务端继续；扩展不会无限运行，也不能承诺读取其他App的全部页面。重复分享按材料身份/内容版本处理，敏感字段提供预览与删除。[Apple App Groups](https://developer.apple.com/documentation/xcode/configuring-app-groups)

音频首发为按住说话、可核对转写、可中断播放。讲解分片段、有字幕、记录真实进度；耳机拔出、来电、蓝牙切换和锁屏分别测试。数据保护策略区分可锁屏播放的公开导览和须解锁的私人表达。

## 11. 离线、境内网络与恢复是核心交付范围

| 情况 | 用户仍能做什么 | 必须如何说明 | 恢复规则 |
| --- | --- | --- | --- |
| 完全离线 | 看已保存Trip、地址、允许下载的讲解/短语；编辑本地草稿 | 快照版本/时间；需要网络的动作明确 | 重新获取当前版本再比较，不覆盖新服务端内容 |
| 高延迟/请求超时 | 看已保存内容、停止等待、稍后回到任务 | “未取得新结果”，不是“你的计划无效” | 同一请求幂等；恢复任务ID |
| SSE断线 | 已交付内容继续可读 | 回应未完整/正在恢复 | sequence去重、有限polling fallback |
| App被杀/后台 | 已提交任务由服务端管理 | 页面关闭不表示任务停止 | 回前台查询权威任务/回执 |
| 配额不足 | 看资料、手改、纠正记忆/删除 | 服务端resetAt及权益 | 不锁成果，不循环发模型请求 |
| 地图SDK失败 | 地点列表、中文地址、经过验证的外部地图入口 | 未取得当前路线 | 不加载伪造地图/错误坐标替代 |
| 许可/权限撤回 | 仍可用自己有权访问的资料 | 受影响内容已不可继续获取 | 取消待发任务，失效缓存，记录清理结果 |
| 旧设备/旧通知 | 先回到当前账号登录/授权 | 不预览旧账号私人内容 | 授权后再取对象，不直接展示通知缓存 |

境内网络不能只测模型API。验收覆盖DNS、TLS、API、鉴权、对象存储、地图、音频、OTA打开、IAP和通知；分别使用海外Wi-Fi、境内普通Wi-Fi、境内移动网络及实际eSIM/漫游样本。不能以某一次VPN环境成功证明在华可用。

只在供应商允许的范围保存地图/媒体和事实快照。路线、库存、报价、营业变化不能用离线旧值冒充当前事实。系统后台调度和APNs是机会性能力，恢复主线必须在用户主动打开时成立。

## 12. 商店、支付与发布到客户

### 12.1 TestFlight和App Store两条交付轨

当前Apple要求真正beta/demo使用TestFlight，App Store提交完整可用版本；现行上传要求为Xcode26+与iOS26 SDK+，仍可维持iOS17 deployment target。TestFlight构建最长测试90天，外部测试首构建需审核；beta购买使用沙盒、不收费。将“Closed Beta”保留为内部招募/学习计划，公开发布是可独立使用的正式1.0，按真实能力描述，不能靠改标签掩盖未完成页面。[App Review 2.1/2.2](https://developer.apple.com/app-store/review/guidelines/)、[SDK要求](https://developer.apple.com/news/upcoming-requirements/?id=02032026a)、[TestFlight](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview/)、[StoreKit Sandbox](https://developer.apple.com/documentation/storekit/testing-in-app-purchases-with-sandbox)

这个区分满足用户“TestFlight和App Store都上线”的要求；审核时长由Apple控制，工程计划不能承诺提交即上线。对测试用户收的沙盒订单不计真实付费意愿或收入。

### 12.2 StoreKit和OTA外跳

VP数字能力按产品合同使用官方IAP。产品页从StoreKit读取本地化价格/期限；purchase pending、取消、退款、恢复、账单重试、成功后网络中断都要有路径。`appAccountToken`用于关联VP账号，服务端核验交易并同步权益；不能只看客户端“购买成功”。消费额度、非续期Trip Pass到期和自动续订Plus语义分别处理，不能依赖同一布尔值。Apple的`currentEntitlements`可包含已结束的非续期订阅，VP须自己验证相关有效期限。[StoreKit Transaction](https://developer.apple.com/documentation/storekit/transaction)、[currentEntitlements](https://developer.apple.com/documentation/storekit/transaction/currententitlements)、[appAccountToken](https://developer.apple.com/documentation/storekit/transaction/appaccounttoken)

酒店等App外消费的实际旅行服务走供应商交易；首发VP只整理需求和验证过的联盟参数，外跳后保持外部未知。没有实时接口时只能比较住宿/房型需求，不保证特定SKU仍可售。UI在CTA附近披露联盟关系、供应商、实际可传参数和需要跳转核对的内容。订单成功须后续由用户声明/凭证/合法供应商结果分别记录，不能从点击推断。[App Review 3.1.3(e)](https://developer.apple.com/app-store/review/guidelines/)

### 12.3 权限与隐私嵌入任务

在真正使用麦克风、位置、通知、上传时才申请对应权限；拒绝位置可手动选地点，拒绝麦克风可文字输入。向第三方AI发送个人数据前，明确接收方和用途并取得所需许可；覆盖模型fallback、OCR、embedding/rerank等实际出站，不只第一个聊天模型。已有效许可可复用，不每轮弹窗。提供应用内账号删除和数据控制，隐私标签、SDK清单与实际网络行为一致。[App Review 5.1.1/5.1.2](https://developer.apple.com/app-store/review/guidelines/)

出包时生成PrivacyInfo.xcprivacy、依赖/SBOM、SDK数据清单和privacy report；填真实使用理由，不能为通过上传随便复制reason code。SDK的隐私声明不是VP的完整隐私声明。[Apple Privacy Manifest](https://developer.apple.com/documentation/bundleresources/adding-a-privacy-manifest-to-your-app-or-third-party-sdk)、[Required Reason API](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api)

### 12.4 发布必须交付的运营材料

- 中英商店描述、真实运行截图、支持网址、隐私页、审查账号/完整可测流程、必要出口与覆盖说明。
- 中英首次使用帮助：怎么导入、怎么区别建议和已确认、怎么看未知、怎么求助、怎么恢复购买、怎么导出/删除。
- UGC若首发开放，提供审核、举报、屏蔽、不当内容处理和可联系负责人；员工内容真实披露。
- App Store商品、订阅/Pass规则、退款/恢复解释，清楚区分数字权益与第三方旅行业务。
- 安装失败、登录链接打不开、境内连不上、旧设备被顶替、订单导入错误的支持脚本。
- 支持状态页/故障公告、客服实际工作时间、首批响应容量；不要使用无人兑现的24小时承诺。
- 每个二进制版本记录API兼容范围、远程能力开关、最低可接受版本与回滚策略；已发二进制不能被瞬间替换，先服务端关闭有问题能力并保持可读。

## 13. 首发真机验收与性能观测

### 13.1 黄金路径

G1：无日期说想法 → 两个方向 → 生成草稿 → 直接编辑 → 对象Ask → diff → 确认 → 关闭/重开 → Web看到同版。
G2：从其他App分享截图 → 选Trip → 解析核对 → 加入材料/候选 → 处理冲突 → 酒店条件外跳 → 返回仍显示外部未知。
G3：Ready缺口 → 看来源和适用范围 → 设置确定时间提醒 → 修改日期 → 原提醒撤销/更新 → 通知打开正确Trip。
G4：Today同Trip → 大字地址/一次中英翻译 → 景点短讲解 → 来电中断 → 用户报告变化 → 局部恢复 → 确认，不改变无关晚餐。
G5：用户完成旅行 → 归档 → 选择长期偏好 → 导出/删除一项记忆 → 新Trip不再使用被删除值。
G6：实际App Store商品 → pending/成功/取消/恢复/退款 → 跨端同权益 → 配额到零仍可看与手改Trip。测试轨与真实付费轨分别记录。

### 13.3 可测的品质目标

以下为待校准目标，不是已达到的SLO：本地按压/选择反馈p95≤100ms；缓存Trip可交互p95≤1s；模型请求获得接收/任务状态p95≤1s（正常测试网络）；首份合格方案分别统计简单/复杂任务P50/P95，不用首token代替；关键手势无可复现焦点丢失/误确认；在基准长聊天与多日Trip上无持续主线程阻塞和内存增长趋势。

同样模型/证据条件比较：重复输入次数、首次有用结果时间、正确局部修改率、能辨认未确认/未知的比例、后台回来的恢复时间、任务中人工介入分钟数。陪伴好感只能作为次指标；实际错误依赖、恢复成功、有效回访才支撑设计。

Simulator能验证布局与部分自动化，不能代替真实后台、音频、强光、网络、IAP和设备权限。CI构建成功与用户体验达标分别记录。

## 15. CI、验收产物与可接手性

建议iOS CI从静态/格式与Swift测试开始，再选固定可用Simulator执行构建/UI路径；保存`.xcresult`、设备/OS、构建hash、截图/录像、后端trace关联。签名发布在受控环境使用账户提供的凭据；普通CI与Simulator验证不需要生产密钥。具体Xcode和Simulator在环境检查后锁定，不能把某台Mac当前名字写成所有Agent环境固定前提。

```bash
xcodebuild -version
xcrun simctl list devices available
xcodebuild -project ios/VisePanda/VisePanda.xcodeproj \
  -scheme VisePanda \
  -destination "platform=iOS Simulator,id=${VP_SIMULATOR_UDID}" \
  CODE_SIGNING_ALLOWED=NO test
```

`VP_SIMULATOR_UDID`须由实际可用设备选定。上面是未来验收命令模板，本轮没有执行；签名Archive/上传另有发布工作流，不能使用Simulator的禁签名选项冒充可发布构建。

仓库交接至少有：原生README、页面状态目录、共享合同、设计token来源、控件/动效规则、中英文案源、SDK与素材许可清单、隐私/删除/离线/通知/恢复购买手册、测试矩阵、发布/回滚步骤、已知未运行项。`docs/handoff.json`写真实结果与一个下一动作；截图/PDF/图像生成物标注concept还是实际App capture。

AI Studio或其他工具输出作为候选代码输入：先验证确为SwiftUI、依赖/许可/文件路径、无密钥/远程执行、编译和代表性状态；按行为逐块迁入，不能因为画面漂亮就覆盖领域逻辑。已有preview-only测试、未跟踪壳和被弃选概念图都应以可恢复方式归档。

## 16. 反证与取舍记录

| 被挑战的想法 | 反例 | 最终处理 |
| --- | --- | --- |
| “完整”意味着首发每个角色一套产品 | 同一用户需重述背景，任务跨页面失联 | 一个VP/Trip，角色隐藏在能力中，完整故事验收 |
| 五Tab天然传统，三Tab才AI-native | 浏览、工具发现是用户已明确需求；减少Tab不改善状态一致 | 五Tab保留；AI体现在对象与动作协作 |
| 手机小，规划留给Web | 用户旅途中必须能局部变更、不能只看计划 | iOS完整编辑；Web精简但可读写同Trip |
| 陪伴一定频繁发话 | 不准时/过期/无关通知会增加焦虑 | 接续为基底，有事实和许可的提醒分级开放 |
| 诚实unavailable就是完成 | 用户仍不知道怎么走下一步 | 验证替代/核实/手动/人工路径真实可用 |
| 美化声音会提高准确性 | 亲切口气可能增加对错误内容的依赖 | 同模型评测适当信任，来源和控制不能被语气遮住 |
| 强模型可自由生成界面 | 布局/确认位置变化会让用户失去控制 | 有限原生组件和真实对象状态；AI只选适合表达 |
| iOS优先可删除Web编辑 | 历史同Trip读写需求与已有有用Canvas行为存在 | 保留轻Planning Studio，无第二套领域真相 |
| TestFlight已收费可证明WTP | TestFlight购买是沙盒 | 只作工程验收，正式IAP才计真实付款 |
| beta也必须立即公开上架 | Apple要求正式完整App，审核不可由团队控制 | 并行准备测试轨与生产1.0轨，条件满足即提交 |
| 新SDK要求等于只支持新iOS | SDK构建要求与deployment target不同 | iOS17主能力+当前合规stable工具链 |
