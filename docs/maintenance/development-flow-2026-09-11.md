## 减少阅读、验证与审核

- 保留 JTCoding 文件，取消所有软件任务默认强制加载。已有完整仓库流程时直接使用；复杂跨模块、新项目缺约定或用户明确指定时按需读取。
- 保持一条集成主线与一条独立准备线。准备任务须解除具体阶段阻塞、交付同一结果的可验证部分，或修复已观察缺陷；不因等待而无限追加加固。
- Issue 正文保留完整验收、依赖、禁区与执行链接；路径、命令、证据、外部条件、观察及回滚集中到相应执行行。73 份生成正文约减少 36%，追加历史及真实进展不删。
- 小改动由实施 agent 自查 diff 加直接检查；普通功能不默认再派独立 agent。权限、数据完整性、资金、迁移及重大共享契约保留独立审查；仓库强制 review 仍有效。
- 同一代码、相关环境与输入的有效证据可复用；进入下一个 skill、交接或审核环节本身不构成重跑理由。新变化、失败或未解风险才触发相关重验。
- CI 精简路径只接受已知导航/流程/任务定义文件；仍执行源码策略 lint、治理测试、契约测试与 docs check。代码、测试、CI、依赖、ADR、运行数据、未知路径和手动运行走完整路径；保留原 job/check 名称。
- 完整 CI 只构建一次，浏览器复用该产物；独立 frontend 命令仍自行构建。同一 PR 新提交取消旧运行。

落实位置：[开发流程](../agents/development-workflow.md)、[CI](../../.github/workflows/quality-pr.yml)、[路径分类器](../../scripts/ci-change-scope.mjs)、[生成器](../../scripts/vpj-program.mjs)。本轮 CI/治理逻辑改变本身走完整检查，不能用它新定义的文档路径跳过自身验证。

## Codex 本机调整

全局移除 1,000,000 上下文窗口和 900,000 自动压缩阈值的手工覆盖，保留内置目录、实验性上下文管理与既有权限。保留较晚写入的 **Astra + max** 选择，不覆盖用户或应用的新设置。JTCoding 改为按需；专业技能使用单一主路由；仅停用存在可用插件替代的本地 Caveman 重复入口，保留 Cavecrew、React 和 JTCoding。

TOML 语义、CLI 配置加载与新进程技能发现已核实。未重启或修改活跃开发线程；本轮已经加载的旧规则不会被追溯撤回。本机完整备份与有冲突保护的恢复脚本另行保存，未将配置或凭据放入仓库。

没有证据证明默认推理档位解释了这条 Dev 线程的速度：有界运行样本实际使用 Astra medium。也未做不同 agent 的同任务对照。因此不宣称配置修改已带来某个提速或费用下降比例。官方说明支持技能渐进加载、项目规则优先与避免无新依据的过度验证：[Skills](https://learn.chatgpt.com/docs/build-skills)、[AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[Astra 指南](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)。
