## 1. 访谈术语

以下记录品牌访谈中需要保持一致的词义。仓库根 CONTEXT.md 由共享 handoff 生成，本文件不改写它的用途，也不建立新的工程架构上下文。

**VisePanda / VP**：同一个面向来华游客的品牌与熊猫旅行助手身份，行前帮助规划，旅途中提供本地帮助。
_避免_：把 Panda 昵称、独立导游品牌或真人到场地陪当成已决定身份。

**安心与确定性**：游客遇到变化时，能得到适合自己的、清楚可执行的下一步。
_避免_：保证任何问题都解决、保证外部供应商成交或支付成功。

**基础长期偏好**：游客明确保存、可纠正、适用范围清楚的稳定旅行偏好，可跨规划服务免费和付费用户。
_避免_：无限自动画像、默认永久采集所有对话、付费即同意扩大资料访问。

**完整服务任务**：一个事先范围明确的服务目标及完成它所需的必要澄清和系统修复；具体计费边界尚待规格化。
_避免_：一条消息必然等于一次完整任务、一个任务无限覆盖整趟旅行。

**月付订阅**：当前优先的 VP 数字服务收费方式，开通后使用行前与在途能力，允许取消未来续费并用完已付周期。具体价格、商品名、账期和额度尚未锁定。
_避免_：到达中国才生效、取消续费立刻清空已付权益、将每位游客长期付费作为前提。

**统一 Agent、相同质量**：免费与付费共用一套 Agent，不人为降低免费回答质量；当前明确的层级差异是使用额度。它不等于取消现有按任务使用工具的架构，也不新增付费专属模型能力。
_避免_：在未有实际且已验证差异时宣传免费质量低、付费 Higher Intelligence。

**eSIM 附加服务**：游客按需选择的外部通信服务，不是每位 VP 购买者必含的商品。创始人表示已有供应商，但供应商身份、价格、供货权限和售后分工尚未核验。
_避免_：所有 VP 套餐必送 eSIM、已验证全网最低价、VP 已完成通信集成。

**支付准备协助**：根据游客已有钱包、卡种和具体问题提供准备与排障路径，账户和核验操作在官方产品中由游客完成。
_避免_：VP 自有钱包、代开户 / 代绑卡、保管支付凭据或保证支付成功。

**Human Task / 真人执行协助**：独立于月付订阅的另一项主要收费服务方向，由真人针对具体旅途问题，在明确范围与真实受理后提供协助。具体价格、范围和免费用户购买资格尚未确定。
_避免_：默认人工行前定制、提交请求即已受理、无限全天候兜底。

### 本轮待澄清的时间与服务概念

- **购买付款时间**：游客完成商品购买并付款的时刻。
- **行前权益开始时间**：购买后哪些准备服务或外部商品权益可以使用的起点；范围待决定。
- **VP 付费服务起算时间**：付费服务有效期开始的时刻。Q39 撤回等待旅行激活，Q42 优先采用月付开通即使用；具体账期仍需商品合同明确。
- **eSIM 套餐起算时间**：由具体供应商套餐规则决定的数据服务起点，不能与 VP 起算合并推断。
- **产品激活指标**：现有主线中采用 / 保存可继续使用的真实 Trip 成果的统计口径；与付费服务激活是不同概念。

基础记忆在付费结束后保留并继续服务免费用户，用于回访连续性。这里不表示无限保留全部原始对话，也不取消用户纠正、删除和限制使用的权利。

## 2. 设计问题与依赖

已明确的前提：长期中国定位；普通自由行客群；行前规划与旅途帮助连续；基础记忆共享；完整服务任务计费方向；eSIM 是附加服务；支付帮助是个性化准备与排障。

Q42–Q44 后的当前分支：

1. 月付方向已明确、一套 Agent 同质量 → 确定免费最低可完成体验、真实额度差异及准确商品表达。
2. Human Task 独立收费方向已明确 → 确定谁能购买、任务范围、受理与服务规则。
3. eSIM 已确定可选，但与“两类主要收费”的关系仍需澄清 → 确定供应商收款 / VP 转售的角色，再核实已有供应商条件。

当前先明确服务范围和购买资格，不锁定具体价格、额度、供应商收款或退款规则；不重新引入已撤回的落地激活设计。

## 3. 已完成轮次 Q39–Q41

### Q39 — 你说的“到了之后才开始计费”，是否指先付钱，后计算在途服务天数？

例如游客提前两个月购买：当时付钱，购买后可以使用约定的行前权益；到了旅行前后再启动在途服务的有效期。还是你希望真正扣款也等到旅行开始？

**当时建议：**优先研究购买时付钱、分阶段提供权益、在途服务稍后起算。付款、行前服务和在途有效期分别说明；具体何时激活及多少天等回答后再定。

**回答：**重新考虑后认为到了中国 / 开始旅行才计时的设计不合适。曾想到改成订阅，又意识到旅行产品未必长期订阅；Trip Pass 又容易让希望在行前体验高级完整 AI 的人等待旅行开始，整体定价逻辑需要对比市场再研究。

**决定状态：**延后旅行激活的方向撤回；订阅与 Pass 都未定案。“还是按照 subscription”在同一答复中被再次质疑，不能孤立摘成已决定订阅。必须支持行前对高级完整 AI 的需求；商品名称、期限、续费与具体权益仍待研究。

### Q40 — eSIM 应该是 VP 套餐里已经买到的东西，还是 VP 帮游客选择和接通的一项可选服务？

如果游客已有漫游套餐或设备不支持 eSIM，你希望他购买 VP 时仍包含一张 eSIM，还是按需要另外选择？

**当时建议：**先以可选服务探索，VP 帮助选择和准备，供应商承担其具体通信商品交付；体验和合作条件清楚后，再评估是否形成含数据权益的礼包。先不强制每个游客都购买同一种外部商品。

**回答：**eSIM 应当是附加服务，希望能够提供便宜的套餐，表示已有供应商。

**决定状态：**可选附加服务已确认；供应商存在是创始人自述，未核实供货、交付或集成。低价是商业目标，“最便宜”不能升级为已经证明的全网最低价承诺。

### Q41 — “支付渠道连接”最希望帮游客完成什么结果？

是让游客看到官方操作说明，还是根据他已有的钱包、卡种和遇到的问题逐步帮助完成准备，必要时再有人协助排障？

**当时建议：**重点研究个性化准备与问题协助：游客在官方 App 自己完成需要的账户和核验操作，VP 帮他判断下一步。付费价值来自减少判断和反复尝试，不只是一页已有的公开教程。

**回答：**同意个性化准备与问题协助的建议。

**决定状态：**方向已接受：游客自己在官方 App 完成账户和核验，VP 根据其情况提供下一步与排障。具体人工服务量、价格、渠道合作及技术集成未确定。

## 4. 已完成轮次 Q42–Q44

### Q42 — 如果购买后就能使用增强服务，你更希望自动续费，还是到期后再买？

两者都覆盖行前与旅途，不需要等待落地。差别在于：按月自动续费、可取消未来续费；或购买一段明确期限，到期后手动续买。

**当时建议：**优先考虑一个按月增强层，取消未来续费后仍用完已付周期；先不增加年付和多种 Pass。自动续费及具体周期必须清楚显示。

**回答：**先采用月付，允许取消未来付费并用完当前周期，作为主要营收方式。主要收费分为月付订阅与 Human Task / 真人协助两类，不写具体定价。

**决定状态：**当前收费方向已接受，具体价格、商品命名、账期、额度与真人范围未定。不是继续并列推出 Trip Pass、年付或其他订阅梯度；eSIM 已接受为附加服务，其收款与收入归属另问。

### Q43 — 无论采用哪种收费方式，能否接受游客只付费一两个月，旅行结束后停止付费？

这里要明确的是：VP 是否允许靠一段集中准备与旅行服务建立价值，而不以每个人长期留在付费层为目标。

**当时建议：**接受这种正常消费周期。观察一次来华旅程中的实际收入、服务成本和口碑；需要时再回来，基础记忆与免费层继续可用。不能以忘记取消续费作为盈利前提。

**回答：**接受集中使用后结束付费的正常周期。免费基础记忆必须保留，通过持续了解用户来维持回访与黏性。

**决定状态：**已接受。不把停止续费自动等同于产品失败；记忆连续性是回访价值，不是已验证留存提升或无限原文保留承诺。

### Q44 — “高级、完整版 AI”最希望让游客感受到哪一种增加？

是可以更密集地使用、少担心额度；还是能处理更多材料和更复杂的安排，给出更充分的比较与调整？两者可以都有，但需要确定哪一个首先构成购买理由。

**当时建议：**以能更完整地处理我的旅行任务为主，足够的使用容量作为保障。免费仍提供可信、个性化的基本帮助；高级不等于免费故意变差，也不自动包含无限媒体或真人。

**回答：**以完整处理旅行任务为主。免费额度较低；实际只做一套 Agent，免费和付费回答质量相同，不做降质。同时提出希望对外让游客感觉付费有更高智慧，甚至将免费描述成质量较低。

**决定状态：**统一 Agent、相同质量、不做免费降质、较低免费额度，是明确的实际产品方向。“同质量但对外声称更高智慧”与该事实不相容，不能作为已确认能力或发布文案。

**表达争议与建议：**记录该想法是为了准确保留决定过程，不授权实施误导性比较。建议突出真实增加的使用额度、更持续的帮助和在额度内完成更多旅行任务，例如内部候选表达“More help throughout your trip”。没有实际、更深的处理能力差异，就不写 Higher Intelligence、更准确、更懂你、推理更强等层级主张。此替代表达尚未获得创始人确认。

### 本轮规划影响

- 收费机制从此前 Free + 非续期 Journey Pass 的工程基线转为优先月付订阅的产品方向，需要规划任务明确对照更新，不能只把 30 天商品改名为月付；本轮不改购买或额度代码。
- Human Task 作为独立收费方向，月付不自动包含无限真人，也不以有人工入口等同于已受理。
- 免费 / 付费一套 Agent、相同质量；当前不建立按会员档位故意降质的模型路线。基础记忆同样适用于免费与到期用户。
- 付费提供的具体额度增量尚未锁定；不沿用旧 Pass 的价格、天数与次数作为月付已确认参数。
- 商品页先说明服务范围和真实额度差异。不得用没有真实依据的智力或准确率比较替代价值证明。
