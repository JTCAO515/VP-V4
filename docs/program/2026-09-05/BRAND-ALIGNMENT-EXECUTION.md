# 品牌方向增量开发计划

本计划将 Q36/Q37 及内容表达方向接回同一 VPJ Program。依据 [工程研究](../../research/VISEPANDA-BRAND-ENGINEERING-ADJUSTMENTS-2026-09-10.md) 与 [ADR-0025](../../adr/ADR-0025-brand-service-task-and-response-semantics.md)。本轮细化26项既有验收、显式替代6条冲突的旧计量规则；不新建同义Issue，不改变原71项身份、状态或210条依赖。正式实施以本规划合入main后的契约、实时blocked_by与实际接口/环境为准。

## 1. 调度优先级

先让服务任务、偏好与响应语义一致，再完成真实只读链路和连续行程成果。优先选择能解除下一个真实验收阻塞的工作，已通过的协议、配对与原生准备复用。一个准备PR可以先交付可验证结果，但其运行父票继续保持未验收。

## 2. 并行分工

按实际槽位默认两条开发线和一条独立审阅线，已有活动任务优先接续。

- 成本线：复用PR #284已合并的#194 durable task/attempt预算、未知费用和并发保护，推进实际worker/provider接入及其获准环境验收。ServiceTask归属字段先与#195协调；不同时另建用户消费账或等待新商品数值。
- 真实输出线：#195/#196版本化输入、结果与恢复事件，接入响应策略；获准接口不足时只交明确准备片段。#193的协议与provider接入由相应owner负责，避免改同一prompt文件。
- 偏好或评测线：根据已合并接口选择#199的任务资格/纠正投影，或#267的内容/语气配对与反例。未决数据留存不自行落永久存储，holdout暴露与调优隔离保留。
- 原生当前缺陷可以作为独立线接续#188；其可访问性与真实对象验收不由这次品牌文案替代。

共享语义、迁移顺序、依赖锁文件和根handoff由主agent协调。每条PR写清Issue、单一结果、专属路径、可用输入、测试与保留的运行门；非作者审阅准确HEAD，必需CI通过后才进入既有授权下的合并流程。HEAD改变需补相应复核，不并行抢改同一文件或共享测试数据库状态。

## 3. 验收与停止扩张

首个完整品牌成果：Free用户明确保存基础偏好 → 新规划正确使用 → 再次使用仍可接续 → 用户报告变化 → 有依据的局部下一步 → 保留已确认约束 → diff确认 → 同一Trip重载一致。必要澄清与系统修复沿同一ServiceTask，内部成本逐attempt核验。

只增加支持这个结果所需的实现与反例。基础模块未接通时，不用更多同类fixture、第二个记忆库、人格agent或新增值模块替代进展。Q38激活/eSIM、人工SLA、新服务额度和未决接收方保持明确决策门；给出具体待办后继续其他独立安全工作。

本次GitHub同步仅修改正文验收及历史替代说明；已有已勾选证据保留，#263保持其完成状态。后续仅在当前Issue全部验收、准确版本合并及真实结果验证后关闭；研究、语气样例和准备PR均不自动完成运行票。
