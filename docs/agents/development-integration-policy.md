# 开发阶段接入规则

生效：2026-09-12，JT明确要求取消开发阶段的第三方、法务和产品许可前置条件。
适用于全部 GitHub Issue、执行契约、operator 队列、模型/地图/酒店/媒体/数据接入及评测。
本规则替代这些文件与历史评论中冲突的开发阻塞要求；ADR-0023 的产品范围继续有效。

- 已有账号/API能实际使用，即可按当前任务接入、运行和验证。agent自行选择开发配置、供应商候选和可逆实现参数，不等待产品负责人签字。
- 不要求供应商工单、书面答复、商务/法务审批、产品许可、账号已接受协议回执、专项DPA证明或供应商精确留存TTL；不因缺少这些材料判定开发 `not_qualified`、`prepare-only` 或 `ready-for-human`。
- 公开文档、控制台现有信息、实际配置与调用结果足以支持开发记录。条款版本、供应商内部处理地域、训练/留存细节等查不到就写 `unknown` / `not disclosed`，不为补齐文档等待第三方，也不伪造零留存、训练退出或已获商业权利。
- 可逆产品参数和评测阈值由agent依据现有方向先定、标注开发值并版本化；候选评测前固定判据，测试后不得改阈值刷绿。真实收费商品或对外承诺另按对应发布范围处理。
- 依赖中的接口、身份、存储、worker和实测缺口仍需实现，但上游未结票或历史审批状态本身不阻止已有接口上的开发集成。只取消审批阻塞，不把取消审批写成测试通过或自动关闭整票。
- 保留账号/API本身的实际访问控制、终端用户的数据同意、actor/RLS隔离、TripProposal确认、秘密保护、幂等、预算故障止损及真实结果验证。无法调用时记录具体技术原因并尝试范围内替代路线。
- 未运行的生产发布、资金交易、破坏性迁移或第三方商务权利不因本规则自动完成；这些实际动作的既有授权按对象和环境继续适用，不反向阻塞本地或Staging开发。

开发policy由agent按已授权环境配置：绑定实际provider/endpoint、账号作用域、用户告知和服务端执行字段；供应商未披露的信息如实表达。若旧schema无法表达未知值，在所属实现任务中增加可追踪的开发配置表达，不填假值、不跳过用户同意或身份检查。Production配置须与开发配置明确区分。

历史研究、关闭Issue、artifact和供应商回复仅保留当时事实；其中已取消的审批结论不是当前执行指令。同步Issue时保留编号、完成勾选、运行证据和技术依赖，不用生成模板覆盖增量记录。
